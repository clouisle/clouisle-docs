管理路由挂载在 `/api/v1/admin` 下，覆盖仪表盘、观测、审计日志、会话、用户、角色、权限、站点设置、模型、SSO、通知、团队、记忆、Agent、工具、Skills、工作流、工作流指标、TOTP、包管理、知识库和消息投递。它们由管理后台使用，响应遵循统一的 `code`/`data`/`msg` 结构，不是面向匿名调用的公共 API。

## 权限模型

每个端点通过依赖声明所需的权限码（`admin:*` 或 `audit:*`）：

- **超级管理员直接放行**：拥有 `is_superuser` 的账号跳过所有权限码校验。
- **其他调用者按权限码判定**：账号必须通过角色持有该端点声明的权限码。权限码由启动时同步的系统权限定义管理，可在**角色**中自由组合（见 `/api/v1/admin/roles`、`/api/v1/admin/permissions`）。
- **API Key 同权校验**：API Key 按其绑定用户的权限集合校验，因此不要给 API Key 授予不必要的 `admin:*` 权限。
- **知识库分组是例外**：`/api/v1/admin/knowledge-bases` 复用平台知识库路由，但会按请求路径前缀把权限码切换为 `admin:knowledge-base:{read,test,create,update,delete}`，并跳过团队成员校验，使管理视图可以跨团队读取和修改知识库。

<Callout type="warn">
  管理端点的鉴权是后端强制的。前端隐藏入口不构成安全边界，第三方集成必须按权限码申请最小权限。
</Callout>

## 分组与权限码

| 分组 | 挂载前缀 | 权限码 |
| --- | --- | --- |
| 仪表盘 | `/api/v1/admin/dashboard` | `admin:dashboard:access` |
| 观测 | `/api/v1/admin/observability` | `admin:dashboard:access` |
| 审计日志 | `/api/v1/admin/audit-logs` | `audit:read`（查询）、`audit:export`（导出、归档） |
| 会话 | `/api/v1/admin/conversations` | `admin:conversation:read`、`admin:conversation:delete` |
| 用户 | `/api/v1/admin/users` | `admin:user:read`、`admin:user:create`、`admin:user:update`、`admin:user:delete` |
| 角色 | `/api/v1/admin/roles` | `admin:role:read`、`admin:role:create`、`admin:role:update`、`admin:role:delete` |
| 权限 | `/api/v1/admin/permissions` | `admin:permission:read`、`admin:permission:create`、`admin:permission:update`、`admin:permission:delete` |
| 站点设置 | `/api/v1/admin/site-settings` | `admin:settings:read`、`admin:settings:update`（归档审计日志另需 `audit:export`） |
| 模型 | `/api/v1/admin/models` | `admin:model:read`、`admin:model:create`、`admin:model:update`、`admin:model:delete` |
| 集成 | `/api/v1/admin/integrations` | `admin:integrations:login:read/update`（登录域）、`admin:integrations:settings:read/update`（内置配置域） |
| 通知 | `/api/v1/admin/notifications` | `admin:notification:create`（创建）、`admin:notification:delete`（删除）；列表按全局管理权限或授权团队收敛 |
| 消息投递 | `/api/v1/admin/deliveries` | `admin:integrations:settings:read`（只读） |
| 团队 | `/api/v1/admin/teams` | `admin:team:read`、`admin:team:create`、`admin:team:delete` |
| 记忆 | `/api/v1/admin/memories` | `admin:memory:read`、`admin:memory:update`、`admin:memory:delete` |
| Agent | `/api/v1/admin/agents` | `admin:app:read`、`admin:app:create`、`admin:app:update`、`admin:app:delete`、`admin:app:publish`、`admin:app:duplicate` |
| 工具 | `/api/v1/admin/tools` | `admin:capability:read`、`admin:capability:create`、`admin:capability:update`、`admin:capability:delete`、`admin:capability:execute` |
| Skills | `/api/v1/admin/skills` | `admin:capability:read`、`admin:capability:create`、`admin:capability:update`、`admin:capability:delete`、`admin:capability:execute` |
| 工作流 | `/api/v1/admin/workflows` | `admin:app:read`、`admin:app:create`、`admin:app:update`、`admin:app:delete`、`admin:app:publish`、`admin:app:duplicate` |
| 工作流指标 | `/api/v1/admin/workflows/metrics` | `admin:dashboard:access`（清缓存需 `admin:settings:update`） |
| TOTP | `/api/v1/admin/totp` | `admin:dashboard:access` |
| 包管理 | `/api/v1/admin/packages` | 需已认证用户（导入/导出按资源自身的访问规则校验） |
| 知识库 | `/api/v1/admin/knowledge-bases` | `admin:knowledge-base:read`、`admin:knowledge-base:test`、`admin:knowledge-base:create`、`admin:knowledge-base:update`、`admin:knowledge-base:delete` |

<Callout type="info">
  Agent、工作流两组共用同一套 `admin:app:*` 权限码，工具与 Skills 两点共用同一套 `admin:capability:*` 权限码；授予其中一组会同时影响另一组。
</Callout>

## 工作流指标

工作流执行指标**不在** `/api/v1/workflows` 下，而在管理前缀下的 `/api/v1/admin/workflows/metrics/*`。其路由自带 `/workflows/metrics` 前缀，因此与管理工作流的 `/api/v1/admin/workflows` CRUD 共存而不冲突。

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/v1/admin/workflows/metrics/dashboard` | 指标看板总览（含运行中的工作流） | `admin:dashboard:access` |
| GET | `/api/v1/admin/workflows/metrics/workflows/{workflow_id}` | 单个工作流的执行指标 | `admin:dashboard:access` |
| GET | `/api/v1/admin/workflows/metrics/nodes` | 全部节点类型指标 | `admin:dashboard:access` |
| GET | `/api/v1/admin/workflows/metrics/nodes/{node_type}` | 指定节点类型指标 | `admin:dashboard:access` |
| GET | `/api/v1/admin/workflows/metrics/running` | 当前运行中的工作流列表 | `admin:dashboard:access` |
| GET | `/api/v1/admin/workflows/metrics/cache` | 指标缓存统计 | `admin:dashboard:access` |
| DELETE | `/api/v1/admin/workflows/metrics/cache` | 清空指标缓存 | `admin:settings:update` |

```bash
curl -X GET "https://your-domain.com/api/v1/admin/workflows/metrics/dashboard" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN"
```

## 消息投递日志 [#delivery-log]

`GET /api/v1/admin/deliveries` 读取飞书与微信 Agent 会话共用的持久化出站队列 `integration_deliveries`。它是**只读**端点，需要 `admin:integrations:settings:read`，超级管理员绕过检查；消息正文、平台资源键（`media_key`）、凭据和文件内容都不会返回。管理后台的**监控** > **投递记录**（`/deliveries`）页面使用同一端点。

`sent` 只表示平台接受了回复请求，不代表接收人已读、打开了卡片或下载了附件。

### 查询参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `provider_type` | repeated `feishu` / `wechat` | 否 | - | 按集成过滤；重复传参匹配任一值（OR） |
| `status` | repeated `pending` / `sending` / `sent` / `error` / `unavailable` / `unknown` | 否 | - | 按投递状态过滤；重复传参匹配任一值（OR） |
| `run_id` | string (UUID) | 否 | - | 按来源 AgentRun 精确过滤 |
| `filename` | string（1–500 字符） | 否 | - | 对产物文件名做不区分大小写的子串过滤 |
| `limit` | integer（1–100） | 否 | `25` | 每页条数 |
| `offset` | integer（≥ 0） | 否 | `0` | 偏移量 |

`provider_type` 内部 OR、`status` 内部 OR，两组之间 AND。响应为 `{items, total, limit, offset}`，按 `created_at`、`id` 倒序。

```bash
curl -X GET "https://your-domain.com/api/v1/admin/deliveries?provider_type=feishu&provider_type=wechat&status=error&status=unknown&limit=25&offset=0" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN"
```

### 状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 已入队，尚未被发送者认领；重启与功能暂停后仍保留 |
| `sending` | 已被某个 worker 在租约内认领；租约过期后转为 `unknown`，不会自动重发 |
| `sent` | 平台接受了回复请求 |
| `error` | 永久失败，如平台拒绝或产物不可用 |
| `unavailable` | 运行已结束，但回复不应发送（渠道关闭、访问被撤销、缺少会话上下文） |
| `unknown` | 发送后的超时；结果不确定，绝不盲目重发 |

### 字段与错误

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string (UUID) | 投递行 ID |
| `provider_type` | string | `feishu` 或 `wechat` |
| `run_id` / `user_id` / `agent_id` | string (UUID) \| null | 来源 AgentRun、连接用户、Agent |
| `chat_id` / `message_id` | string \| null | 平台会话 ID / 消息 ID |
| `event_key` | string | 事件标识，如 `received`、`final`、`final-asset`、`ask:<tool-call>` |
| `sequence` | integer | 同一事件内分片顺序 |
| `kind` | string | `text`、`markdown`、`asset` 等 |
| `filename` / `content_type` / `size` | string / string / integer \| null | 产物名称、MIME 类型、字节数 |
| `media_type` | string \| null | 平台媒体类型 |
| `status` | string | 上表状态之一 |
| `error` | string \| null | 稳定失败键，用于行为判断与本地化 |
| `error_detail` | string \| null | 平台原始错误：消息、HTTP 状态、错误码与响应片段 |
| `has_media_key` | boolean | 是否已保存平台资源键；键本身不返回 |
| `created_at` / `updated_at` | string (ISO 8601) | 创建与最后更新时间 |

`error` 是稳定的机器可读键（如 `feishu_agent_asset_upload_failed`）；`error_detail` 保留平台返回的原文、HTTP 状态与错误码，便于定位权限、参数或大小问题。

<Callout type="warn" title="与通知投递不是同一张表">
  `GET /api/v1/admin/deliveries` 与 `integration_deliveries` 只覆盖飞书/微信 Agent 会话。站内通知的 email / webhook / feishu 外部发送记录在 `notification_deliveries`，通过通知管理接口的 `deliveries[]` 读取；微信不是通知渠道。
</Callout>

### 升级关系

单表 `integration_deliveries` 取代旧的 `feishu_agent_deliveries` 与 `wechat_agent_deliveries`。首次启动时 API 复制旧表数据并删除旧表，因此 **API、所有 worker 与 Beat 必须部署到匹配版本**：旧进程会向已删除的表写入。仅回滚应用镜像无法重建队列表；回滚必须使用升级前的数据库备份。

页面行为、筛选与排障建议见[投递记录](../usage/guides/integrations/delivery-log.mdx)。

## 集成建议

- 第三方应用优先使用 Agent、工作流、会话和知识库资源端点，而不是管理端点。
- 管理自动化必须固定 Clouisle 版本，记录所需权限码，并在升级前检查 OpenAPI Schema。
- 审计和用户管理操作包含敏感数据，应使用短期密钥并配合最小限速。
- 只有确实需要跨团队运维时才授予 `admin:*`；日常使用应通过团队角色授予平台权限（如 `workflow:read`、`kb:read`）。

## 常见错误

| HTTP / code | 含义 |
| --- | --- |
| `401 / 2000` | 缺少认证 |
| `403 / 3000` | 缺少对应权限码 |
| `404 / 4000` | 资源不存在 |
| `1001` | 请求参数校验失败 |
