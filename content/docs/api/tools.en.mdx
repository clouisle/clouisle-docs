## Authentication

All endpoints require an authenticated JWT user session. API-key authentication is not accepted by these management and execution routes.

**Required permissions:**
- `tool:read` — View tools
- `tool:create` — Create tools
- `tool:update` — Update tools
- `tool:delete` — Delete tools
- `tool:execute` — Execute/test tools

## Tool Filter Options

```
GET /api/v1/tools/filters
```

Requires `tool:read`. Returns the filter options for the tools the caller can access, for building list-page filters.

```json
{
  "code": 0,
  "data": {
    "types": [
      { "value": "builtin", "label": "builtin" },
      { "value": "custom", "label": "custom" },
      { "value": "mcp", "label": "mcp" }
    ],
    "categories": [{ "value": "search", "label": "search" }],
    "statuses": [
      { "value": "enabled", "label": "enabled" },
      { "value": "disabled", "label": "disabled" }
    ],

    "creators": [{ "value": "alice", "label": "alice" }]
  },
  "msg": "success"
```

`categories` is every defined tool category combined with any custom category present on accessible tools; `teams` lists teams the user can access; `creators` lists the distinct creator names of accessible tools.

## List Legacy Team Tools

```
GET /api/v1/tools/legacy?team_id={team_id}
```

Legacy compatibility endpoint returning a team's tools grouped by kind (`builtin` / `custom` / `mcp`). New integrations should prefer [List Tools](#list-tools).

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `team_id` | string | Yes | - | Team UUID |
| `include_shared` | boolean | No | `true` | Include tools shared with the team by other teams |

`builtin` always contains the full builtin tool list; `custom` and `mcp` contain the team's own tools (excluding other members' private tools) and, when `include_shared=true`, tools shared into the team.

## List Builtin Tools

```
GET /api/v1/tools/builtin
```

Returns every builtin tool (including the sandbox tools `artifact`, `bash`, `edit`, `read`, `write`). Builtin tools have no database record, so their objects have `id: null` and `custom_type: null`.

## List File Parsers

```
GET /api/v1/tools/file-parsers?team_id={team_id}
```

Returns the tools usable as document parsers for file uploads: builtin parsers (such as `markitdown`) plus the team's enabled custom tools with `category=file`. Requires `tool:read` and team membership.

## Test Tool

Execute a tool once by name with arguments. **Note:** There is no standalone `POST /tools/{tool_id}/execute` endpoint; use this unified interface instead.

### Request Body

```json
{
  "name": "web_search",
  "arguments": {
    "query": "artificial intelligence",
    "num_results": 5,
    "search_engine": "auto"
  }
}
```

### Request Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | Tool name |
| `arguments` | object | No | Tool arguments |

<Callout type="info" title="web_search arguments">
  `web_search` takes `query`, `num_results` (default `5`, max `10`), and `search_engine` (`auto` or an enabled engine). The test page lists only site-enabled engines; a disabled engine or a missing credential yields `data.success: false` with an error message and no automatic fallback.
</Callout>

### Request Example

```bash
curl -X POST "https://your-domain.com/api/v1/tools/test" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "web_search",
    "arguments": {
      "query": "artificial intelligence",
      "num_results": 5,
      "search_engine": "auto"
    }
  }'
```

### Response

**Success (200 OK):**

```json
{
  "code": 0,
  "data": {
    "name": "web_search",
    "success": true,
    "result": {
      "query": "artificial intelligence",

        {
          "title": "Artificial Intelligence - Wikipedia",
```

**Error (400 Bad Request):**

```json
  },
  "msg": "Validation failed"
```

## Execute Code

Run JavaScript/Python code directly in the sandbox without saving a tool.

```json

  "params": {},
  "timeout": 30,
  "python_packages": ["requests"]
}
```

| Field | Type | Required | Description |

## Create Custom Tool

Create a custom tool. `team_id` is a required query parameter.

### Query Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `team_id` | string | Yes | Team UUID that owns the tool |

### Request Body

```json
{
  "name": "crm_lookup",
  "display_name": "CRM Lookup",
  "description": "Look up customer information in CRM",
  "category": "data",
  "type": "custom",
  "custom_type": "http",
  "icon": "👤",
  "parameters": [
    {
      "name": "customer_id",
      "type": "string",
      "required": true,
      "description": "Customer ID to lookup"
    }
  ],
  "http_config": {
    "method": "GET",
    "url": "https://api.crm.example.com/customers/{customer_id}",
    "headers": {
      "X-API-Key": "crm_..."
    },
    "timeout": 30
  },
  "credentials": {},
  "is_enabled": true
}
```

### Request Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | Tool name (unique identifier, max 100 chars) |
| `display_name` | string | Yes | Display name (max 100 chars) |
| `description` | string | No | Tool description |
| `icon` | string | No | Icon (emoji or URL, max 100 chars) |
| `category` | string | No | Tool category (default: `other`) |
| `type` | string | No | Tool type: `builtin`, `custom`, `mcp` (default: `custom`) |
| `custom_type` | string | No | Custom tool type: `http`, `code`, `database` (only for `type=custom`) |
| `visibility` | string | No | Tool visibility: `private` or `team` (default: `private`) |
| `parameters` | array | No | Parameter definitions (`name`, `type`, `description`, `required`, `enum`, `default`) |
| `http_config` | object | No | HTTP config (`method`, `url`, `headers`, `query_params`, `body_template`, `content_type`, `form_fields`, `timeout`, `response_path`) |
| `code_config` | object | No | Code config (`language`, `code`, `command`, `python_packages`, `js_packages`, `python_package_index_url`, `node_package_registry_url`, `artifacts`, `limits`) |
| `database_config` | object | No | Database config (`db_type`, `host`, `port`, `database`, `username`, `password`, `ssl`, `url`, `db`, `auth_source`, `timeout`, `max_limit`) |
| `mcp_config` | object | No | MCP Server config (`transport`, `command`, `args`, `env`, `url`, `headers`) |
| `credentials` | object | No | Tool credentials |
| `is_enabled` | boolean | No | Enabled status (default: true) |

`name` must match `^[a-zA-Z][a-zA-Z0-9_]*$` (starts with a letter, letters/digits/underscores only), otherwise `1001 tool_name_invalid_format`; a duplicate name within the team returns `5001 tool_name_exists`.

```bash
    "type": "custom",
    "custom_type": "http",
    "parameters": [
      {
        "name": "customer_id",
        "type": "string",
        "required": true
      }
    ],
    "http_config": {
      "method": "GET",
      "url": "https://api.crm.example.com/customers/{customer_id}"
    }
  }'
```

**Success (200 OK):**

## Toggle Tool

```
POST /api/v1/tools/{tool_id}/toggle
```

Flips a tool's enabled state. There is no request body. Only database-backed tools (`custom`, `mcp`) can be toggled; builtin tools are always enabled. The caller must be the tool creator or a team admin and hold `tool:update`.

```bash
curl -X POST "https://your-domain.com/api/v1/tools/tool-789/toggle" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

**Success (200 OK):** returns the updated `ToolDetailOut` with `is_enabled` flipped and `msg` set to `"Tool updated successfully"`.

## Duplicate Tool

```
POST /api/v1/tools/{tool_id}/duplicate
```

Copies a tool within its owning team. Requires `tool:create` and the **admin** role in the tool's team.

```bash
curl -X POST "https://your-domain.com/api/v1/tools/tool-789/duplicate" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

Copy rules:

- Visibility is always `private` and `is_enabled` is always `false` (enable it manually after copying).
- The name gets a `_copy` suffix, falling back to `_copy_1`, `_copy_2`, … until unique.
- The display name gets a ` (Copy)` suffix.
- `code_config`, `database_config`, `mcp_config`, and `credentials` are copied.

<Callout type="warn">
  Duplication copies `credentials`, so the copy inherits the original tool's secrets. Rotate or delete unneeded credentials after copying.
</Callout>

## Cross-Team Tool Sharing

Share custom or MCP tools with other teams within the workspace. Sharing requires `admin` or `owner` role in the tool's owner team; a tool cannot be shared with its own team.

### Share Tool

```
POST /api/v1/tools/{tool_id}/share
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `team_id` | string | Yes | Target team UUID |
| `permission` | string | No | `read_only` (view and use) or `read_execute` (view, use, and see execution results), default `read_only` |

```bash
curl -X POST "https://your-domain.com/api/v1/tools/tool-789/share" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"team_id": "team-456", "permission": "read_execute"}'
```

Returns the created share record with `id`, `tool_id`, `tool_name`, `tool_display_name`, `shared_with_team_id`, `shared_with_team_name`, `permission`, `shared_by_id`, `shared_by_name`, and `shared_at`.

### List Shares for a Tool

```
GET /api/v1/tools/{tool_id}/shares
```

Returns `{ "shares": [...], "total": N }`. Accessible only to members of the tool's owner team.

### List Tools Shared With a Team

```
GET /api/v1/tools/shared-with-me?team_id={team_id}
```

`team_id` is a **required query parameter**. Items in the list return `is_owned: false`, `owner_team_id`, `owner_team_name`, and `share_permission`.

### Revoke Share

```
DELETE /api/v1/tools/{tool_id}/share/{team_id}
```

## Tool Configuration (Credentials)

Tool configurations store credentials (API keys, tokens) for **builtin tools**, either globally (superusers only) or per team. Custom tools keep credentials on the tool record instead, and web search now uses the site-level configuration.

```
GET    /api/v1/tools/config?team_id={team_id}
GET    /api/v1/tools/config/{tool_name}?team_id={team_id}
POST   /api/v1/tools/config?team_id={team_id}
PUT    /api/v1/tools/config/{tool_name}?team_id={team_id}
DELETE /api/v1/tools/config/{tool_name}?team_id={team_id}
```

| Parameter | Location | Required | Description |
| --- | --- | --- | --- |
| `team_id` | Query | No | Team UUID; omit to operate on the global configuration (superusers only) |
| `tool_name` | Path | Yes (get/put/delete) | Tool name |

Create body:

```json
{
  "tool_name": "example_tool",
  "credentials": {
    "API_KEY": "..."
  }
}
```

Update body contains only `credentials`:

```json
{
  "credentials": {
    "API_KEY": "..."
  }
}
```

Permissions and behavior:

- With `team_id`, create/update/delete require the team **admin** role and reads require team membership.
- Without `team_id`, both reads and writes are limited to superusers.
- Reading a team configuration for a known builtin tool name that has no record yet creates an empty configuration automatically; an unknown name returns `404`.
- Deleting returns `data: null`.

<Callout type="warn">
  The generic tool-config endpoints do **not** accept `web_search`: `GET/PUT/DELETE /api/v1/tools/config/web_search` return `400 web_search_site_managed`, and the list endpoint filters the record out. Search credentials live only in the site configuration described below.
</Callout>

## Site Web Search Configuration

The site owns exactly one web search configuration; teams and Agents can only choose among enabled engines.

### Read the configuration

```
GET /api/v1/admin/tools/web-search/config
```

Permission: `admin:capability:read`.

```json
{
  "code": 0,
  "data": {
    "default_engine": "tavily",
    "tavily_enabled": true,
    "bocha_enabled": false,
    "searxng_enabled": false,
    "deepseek_enabled": false,
    "tavily_api_key_configured": true,
    "bocha_api_key_configured": false,
    "deepseek_api_key_configured": false,
    "searxng_base_url": "",
    "searxng_auth_token_configured": false,
    "legacy_credentials_present": false
  },
  "msg": "success"
}
```

Secrets appear only as `*_configured` booleans; the endpoint never returns plaintext. `legacy_credentials_present` signals archived legacy team/Agent credentials from an upgrade. When the site has never saved a configuration, `default_engine` reads back as the fallback `tavily`, all four `*_enabled` flags and every `*_configured` flag are `false`, and `searxng_base_url` is an empty string.

### Update the configuration

```
PUT /api/v1/admin/tools/web-search/config
```

Permission: `admin:capability:update`. Request fields:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `default_engine` | string | Yes | `tavily`, `bocha`, `searxng`, or `deepseek`; must be an enabled engine |
| `tavily_enabled` | boolean | Yes | Enable Tavily |
| `bocha_enabled` | boolean | Yes | Enable Bocha |
| `searxng_enabled` | boolean | Yes | Enable the self-hosted SearXNG |
| `deepseek_enabled` | boolean | Yes | Enable DeepSeek Search |
| `tavily_api_key` | string/null | No | Write-only, at most `1024` characters |
| `bocha_api_key` | string/null | No | Write-only, at most `1024` characters |
| `deepseek_api_key` | string/null | No | Write-only, at most `1024` characters |
| `searxng_base_url` | string/null | No | Instance root, at most `2048` characters; may include a reverse-proxy subpath but not `/search`, a query string, a fragment, or userinfo |
| `searxng_auth_token` | string/null | No | Write-only; optional bearer, requires an HTTPS base URL |

Secret partial-update semantics: **omitted or `null` keeps** the stored value, **an empty string `""` clears** it, and a non-empty string replaces it. `searxng_base_url` also supports clearing with an empty string. The body is strict (`extra="forbid"`), so unknown fields fail validation.

Save-time validation:

- Enabling `tavily` / `bocha` / `deepseek` without its secret → `web_search_engine_not_configured`.
- Enabling `searxng` without a base URL → `web_search_searxng_base_url_required`; a token with a non-HTTPS base URL → `web_search_searxng_https_required`.
- An invalid `default_engine` or one that points at a disabled engine → `web_search_default_engine_invalid` / `web_search_default_engine_disabled`.
- A malformed SearXNG base URL → `web_search_searxng_base_url_invalid`; changing the base URL while a token is stored requires replacing or clearing that token in the same request, otherwise `web_search_searxng_token_confirmation_required`.
- An enabled SearXNG URL passes the SSRF check on save and on every request.

### Test the saved configuration

```
POST /api/v1/admin/tools/web-search/test
```

Permission: `admin:capability:execute`.

```json
{
  "query": "Shanghai weather today",
  "engine": "auto"
}
```

`query` is `1-1000` characters and must not be blank; `engine` defaults to `auto` and may name a specific engine. The response `data` mirrors a tool run: `query`, `success`, `search_engine`, and `results` (`title`, `url`, `content`, `score`, `citation_id`), with `error` and `success: false` on failure. It uses the **saved** site configuration and never accepts ad-hoc secrets.

### List available engines

```
GET /api/v1/tools/web-search/engines
```

Permission: `tool:read`. Returns only the identifiers of site-enabled engines, for example `["tavily", "deepseek"]`; `auto`, credential state, and the SearXNG URL never appear here. Agent and workflow engine dropdowns are built from this endpoint.

## MCP & Database Tool Diagnostics

### Discover MCP Server Tools

```
POST /api/v1/tools/mcp/list-tools
```

Connect to an MCP server dynamically to inspect its declared tools before creating a tool record.

```json
{
  "mcp_config": {
    "transport": "sse",
    "command": null,
    "args": [],
    "env": {},
    "url": "https://mcp.internal.example.com/sse",
    "headers": {}
  }
}
```

`mcp_config.transport` accepts `stdio`, `sse`, and `http`: `stdio` uses `command`, `args`, and `env`; `sse`/`http` use `url` and `headers`.

The response returns `tools` (each with name, description, and input parameter schema), `server_name`, and `server_version`.

<Callout type="warn">
  This endpoint initiates a real network request or process launch. Target URLs are subject to the deployment outbound network allowlist.
</Callout>

```
POST /api/v1/tools/database/test-connection
```

```json
  "db_type": "postgresql",
  "host": "db.example.com",
  "port": 5432,
  "database": "analytics",
  "username": "readonly",
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `db_type` | string | Yes | `postgresql`, `mysql`, `redis`, `mongodb` |
| `host` | string | No | Hostname or IP |
| `port` | integer | No | Port |
| `database` | string | No | Database name |
| `username` | string | No | Username |
| `password` | string | No | Password |
| `ssl` | string \| boolean | No | SSL mode |

| `max_limit` | integer | No | Maximum rows returned (1–1000, default 100) |

Returns `400` with `msg` set to the failure reason (such as `database_connection_failed`) when connection testing fails.

## Error Codes

| Code | Message | Description |
| --- | --- | --- |
| `4000` | Not found | Tool does not exist |
| `4004` | Team not found | Target team does not exist |
| `3000` | Permission denied | Insufficient permissions (sharing requires team admin) |
| `3003` | Team admin required | Admin role required in the tool owner team |
| `5001` | Already exists | A tool with the same name already exists in the team |
| `5104` | Duplicate name | The tool is already shared with that team, or the tool configuration already exists |
| `1001` | Validation failed | Invalid request data (including an invalid tool-name format) |
| `1002` | Bad request | Sharing to the tool's own team or failed connection test |

> **Note:** No per-endpoint rate limits are implemented. There is no rate-limit middleware on these endpoints. Codes `6300`-`6306` are reserved for SSO errors and are not used by the Tools API.

## Code Examples

### Python

```python
import requests

def list_tools(token):
    """List all available tools."""
    url = "https://your-domain.com/api/v1/tools"
    headers = {
        "Authorization": f"Bearer {token}"
    }

    response = requests.get(url, headers=headers)
    result = response.json()

    if result['code'] == 0:
        return result['data']['items']
    else:
        raise Exception(f"Error: {result['msg']}")

def test_tool(token, name, arguments):
    """Execute a tool once."""
    url = "https://your-domain.com/api/v1/tools/test"
    headers = {
        "Authorization": f"Bearer {token}",
        "Content-Type": "application/json"
    }
    data = {
        "name": name,
        "arguments": arguments
    }

    response = requests.post(url, headers=headers, json=data)
    result = response.json()

    if result['code'] == 0:
        return result['data']['result']
    else:
        raise Exception(f"Error: {result['msg']}")

# Usage
tools = list_tools("YOUR_TOKEN")
for tool in tools:
    print(f"Tool: {tool['display_name']} ({tool['category']})")

# Execute web search
result = test_tool(
    "YOUR_TOKEN",
    "web_search",
    {"query": "artificial intelligence", "num_results": 5, "search_engine": "auto"}
)
print(f"Search results: {result['results']}")
```

### JavaScript

```javascript
async function listTools(token) {
  const response = await fetch(
    'https://your-domain.com/api/v1/tools',
    {
      headers: {
        'Authorization': `Bearer ${token}`,
      },
    }
  );

  const result = await response.json();

  if (result.code === 0) {
    return result.data.items;
  } else {
    throw new Error(result.msg);
  }
}

async function testTool(token, name, arguments) {
  const response = await fetch(
    'https://your-domain.com/api/v1/tools/test',
    {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        name: name,
        arguments: arguments,
      }),
    }
  );

  const result = await response.json();

  if (result.code === 0) {
    return result.data.result;
  } else {
    throw new Error(result.msg);
  }
}

// Usage
const tools = await listTools('YOUR_TOKEN');
tools.forEach(tool => {
  console.log(`Tool: ${tool.display_name} (${tool.category})`);
});

// Execute web search
const result = await testTool(
  'YOUR_TOKEN',
  'web_search',
  { query: 'artificial intelligence', num_results: 5, search_engine: 'auto' }
);
console.log('Search results:', result.results);
```
