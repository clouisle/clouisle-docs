本教程用一组产品文档构建 RAG Agent，重点验证分块、混合检索、重排序、引用和失败诊断。

<Callout type="info" title="前置条件">
  当前团队有 `embedding`、`chat` 模型和可选 `rerank` 模型。准备一个 PDF、Markdown 或 DOCX 产品文档，单文件不超过站点当前上传限制（默认 `50MB`，可由管理员在站点设置中调整，范围 `1-1024MB`）。
</Callout>

## 最终结果

Agent 能回答文档中的问题并返回来源；检索实验室能解释每个结果在向量、全文、融合和重排阶段的分数。

## 步骤 1：创建知识库并选择模型

<Callout type="info">嵌入模型一旦选定就不要随意更换，必须在处理文档前确认。</Callout>

1. 创建知识库；它会归属于顶部团队切换器中当前选中的团队。
2. 选择 `embedding` 模型和可选 `rerank` 模型。
3. 分块大小使用 `1000`，重叠使用 `100`。
4. 保存。

## 步骤 2：导入并处理文档

<Callout type="info">先预览分块，确认标题、段落和表格没有被切得过碎。</Callout>

1. 选择**上传文档**，上传产品文档。
2. 文档进入**等待中**后选择**预览分块**。
3. 检查分块数、重叠长度和文本清理效果。
4. 选择**开始处理**，等待状态变为**已完成**。

  <img src="https://rustfs-endpoint.yhnotes.com/content/tutorial-rag-document-ready.png" alt="文档处理完成" />
  <figcaption>文档处理完成</figcaption>

## 步骤 3：运行检索实验室

<Callout type="info">用固定问题对比配置，避免凭感觉修改生产参数。</Callout>

1. 打开**命中测试**，输入文档中有明确答案的问题。
2. 分别运行向量、全文和混合检索。
3. 对比结果重合数、阶段耗时、最终分数和诊断。
4. 保存表现最佳的本地预设。
5. 选择**应用到生产**前确认至少一个混合权重大于 `0`。

## 步骤 4：创建并绑定 Agent

1. 创建 Agent，选择 `chat` 模型。
2. 关联刚才的知识库，检索模式使用**混合检索**，召回数量（Top K）使用 `5`，相似度阈值保持 `0.3`。
3. 关联知识库后才出现检索时机选项 **Agentic RAG** / **Naive RAG** / **关闭**：**Agentic RAG** 由模型自行决定何时检索，**Naive RAG** 每条消息都自动检索，**关闭**则不做检索增强。未关联知识库时该选项不显示，Agent 只做普通对话。
4. 提示词要求“仅基于来源回答；无法找到答案时说明不确定”。
5. 预览并发布。

## 验收与故障排查

- 文档问题能引用正确文档。
- 无答案问题不会生成无依据断言。
- 检索实验室的诊断为空，或给出的提示能解释原因。
- 更换嵌入模型后必须重建索引，否则新旧向量不兼容，检索会整体失效。
- 召回不到内容时按顺序检查：文档是否已完成处理且分块不为空；嵌入模型与重排模型是否可用、是否已授权给当前团队；检索模式、召回数量与相似度阈值是否合适（阈值过高会滤掉全部结果）；知识库是否已共享到当前团队。
- 以上都正常仍无结果时，联系部署管理员确认检索服务运行正常。调参方法与诊断字段见[检索与质量调优](../guides/knowledge/retrieval.mdx)。
