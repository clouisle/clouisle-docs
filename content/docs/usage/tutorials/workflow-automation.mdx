本教程构建一个“工单分流”工作流：接收用户输入，用问题分类节点判断优先级，调用知识库和外部 HTTP API，最后输出工单结果。

<Callout type="info" title="前置条件">
  当前团队有 `chat` 模型、至少一个已处理知识库和可调用的测试 HTTP 端点。要发布 Webhook，需要创建 API Key 并具备工作流发布权限。
</Callout>

## 步骤 1：定义开始输入

<Callout type="info">明确输入契约，后续节点才能通过变量选择器获得稳定类型。</Callout>

创建工作流并选择**用户输入**开始节点，添加：`customer_id`（文本，必填）、`message`（段落，必填）、`priority`（下拉选项，可选，默认 `normal`）。

## 步骤 2：分类和分支

<Callout type="info">先分类再执行副作用操作，避免把所有请求都送进同一条处理路径。</Callout>

1. 添加**问题分类**节点，定义 `billing`、`technical`、`general` 三个类别。
2. 添加**条件分支**，将高优先级或技术问题导向知识库与 API 分支。
3. 使用变量选择器连接输入和分类输出。

## 步骤 3：检索和调用 HTTP API

<Callout type="info">工具节点只接收必要参数；API Key 这类敏感信息放进工具的**请求头**，不要作为参数传进去。</Callout>

1. 添加**知识库检索**，查询使用 `{message}`，Top K 使用 `5`。
2. 编辑器节点面板不提供裸 HTTP 节点，请在**能力** > **工具** > **创建工具** > **HTTP API** 创建一个 HTTP 工具：方法选择 `POST`，URL 填测试端点，**超时时间**保持默认 `30`。
3. 回到工作流添加**工具**节点，选择刚创建的 HTTP 工具。
4. 在参数配置中把 `customer_id`、分类结果和知识库摘要映射到工具的入参，并测试失败分支。

## 步骤 4：定义输出并调试

1. 添加**输出**节点，映射 `category`、`ticket_id`、`answer` 和 `sources`。
2. 打开**检查清单**，修复所有错误。
3. 在编辑器选择**运行**打开**测试运行**抽屉，用**调试（使用草稿）**分别测试正常请求、未知分类、API 超时和无知识库结果。
4. 在运行抽屉的**追踪**里查看每个节点的输入输出、耗时和错误。

## 步骤 5：发布 Webhook

1. 打开**工作流设置** > **触发器**，把**触发方式**设为 **Webhook** 并保存。
2. 选择**发布**，运行页呈现选择**表单与结果**。
3. 在**访问 API**复制 Webhook URL 与示例请求。
4. 用自己的 API Key 替换示例里的占位值并发送 JSON 请求；随后在**日志**页或运行抽屉查看执行进度与结果。

<Callout type="success" title="验收标准">
  正常请求返回工单 ID；条件分支按分类执行；HTTP 失败可在追踪中定位；Webhook 只接受带有效 API Key 的请求；日志显示节点状态、耗时和输出。
</Callout>
