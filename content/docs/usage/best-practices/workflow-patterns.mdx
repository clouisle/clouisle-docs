运用四种典型设计模式，构建结构清晰、可维护的工作流。

## 顺序模式

线性执行：A → B → C → D

**适用场景**：文档处理流水线

## 并行模式

并发执行：A → (B, C, D) → E

**适用场景**：多源数据聚合

## 条件模式

分支逻辑：A → if(condition) → B else C

**适用场景**：内容路由

## 循环模式

迭代执行：A → while(condition) → B → A

**适用场景**：批量处理与有界重试

配置显式终止条件和有限上限。工作流编辑器默认循环限制为 10 次；执行器强制最大循环 1000 次。处理数组或对象时使用迭代节点，使每个条目都有清晰的输入和输出，而非依赖无界循环。

**安全检查清单**：
- 根据输入大小设置适当的上限
- 确保条件能朝着终止方向推进
- 处理空输入和单条失败
- 将重试与业务迭代分开
