An Agent is an AI application for multi-turn conversations. It combines a chat model authorized to a team with system prompts, variables, Knowledge Bases, tools, memory, attachments, and media generation settings.

### Orchestration and runtime

The Agent editor page consists of an orchestration form and a live preview. Prompts support `{{variable_name}}`; user variables can be text, paragraph, dropdown options, number, checkbox, plus array, object, and file/image types (file variables receive attachments). The built-in `{{query}}` variable represents the current user input.

An Agent performs up to `1-200` tool calls per turn, with a default of `5`. When the limit is reached, the turn stops calling tools instead of looping indefinitely.

Runs are asynchronous and resumable: after sending a message you can leave the page, refresh, or switch conversations, and on return the generated content and subsequent events are still there without resending. A run can also park in a "waiting for answer" state while the user answers a question the model asked; the form is restored after a refresh.

Tasks are **never retried automatically**. A retry would repeat model and tool calls with side effects, so the platform only starts over when the user resends. If a run makes no progress for a long time, the execution service is unavailable — contact operations instead of clicking send repeatedly.

### RAG modes

| Mode | Behavior |
| --- | --- |
| Off | No Knowledge Base retrieval |
| Auto (Naive RAG) | Automatically retrieves linked Knowledge Bases before each model call |
| Agentic (default) | The Agent decides when to retrieve Knowledge Bases |

Each linked Knowledge Base can independently configure its retrieval method, Top K, and threshold. The retrieval method is vector, full-text, or hybrid.

### Conversations, branching, and compression

A conversation is created automatically with the first message. Users can edit messages or regenerate replies; the system keeps multiple versions and an active branch, and switching branches never loses the others.

Long conversations check the context budget before model calls and, when needed, compress earlier reasoning, tool results, and historical turns while keeping the most recent raw turns. The compression summary targets `1000` tokens by default (configurable `128-8000`). Users still see the full conversation; only the history sent to the model is compressed.

### Interaction, citations, and artifacts

- **Interactive questions**: when enabled, the model can ask a question mid-answer and pause the turn; once the user submits the form in the chat page, the same answer continues from that point. Questions are off by default, and a pending question is saved with the conversation, so a refresh or a return to the conversation restores the form.
- **Citations**: with citations enabled, Knowledge Base retrieval, web tools, and parsed attachments can all be cited. Citation markers in the answer are clickable, and the interface lists only the sources actually cited; content without a source ID is not presented as a citation.
- **Attachments and artifacts**: user attachments, generated images/videos, and code artifacts belong to **the current conversation** and can be accessed only from the conversation or workflow run that produced them. Downloads require the current sign-in credentials, the platform exposes no public URL, and an address cannot be copied into another conversation for reuse.
- **Execution trace**: retrieval, compression, reasoning, tool calls, user guidance, and media results are folded into the thought timeline in the order they occur, and remain expandable after a refresh.
- **Display switches**: hiding reasoning, tool calls, message actions, and the artifact list only affects presentation; it changes neither stored data nor access permissions. See the [Agent configuration reference](../../reference/agent-config.mdx) for field meanings.

### Memory

Memory is **off** by default. Once enabled, an Agent can retrieve user information across conversations: each turn injects up to `10` memory entries by default (configurable `1-50`), automatic extraction is on by default, and the minimum importance for auto-extracted memories defaults to medium (low, medium, or high). Turning automatic extraction off only stops writes; already-stored memories are still retrieved and injected.

Memory and conversation context have different scopes: conversation context belongs to a single conversation, while memory persists per **user** and retrieval does not separate by Agent or team. Memories created in one Agent are therefore visible to another Agent for the same user; be careful when enabling it for shared accounts or one account acting under several identities. Users can review and delete their own memories on the **Memories** page.

### Publishing and visibility

An Agent has only two states: **Draft** and **Published**. Visibility is **Private** or **Team**; legacy public visibility is treated as team visibility. After publishing, the shared conversation page, embeddable page, and API are available; publish permission and edit permission are controlled separately.
