工作流用一张有向节点图把多步骤任务固定下来：开始节点定义输入，中间节点处理数据或调用能力，输出节点决定最终结果。与 Agent「边想边做」不同，工作流的顺序、分支与并行关系是编排好的，同一份输入会沿同一条路径执行，因此适合需要可重复、可审计结果的场景。

### 草稿与发布

- 编辑中的工作流是**草稿**，可以随时保存、随时调试运行；调试执行的是当前草稿，不影响线上效果。
- 只有**已发布**的版本才能正式运行：运行表单、触发器与外部调用都指向已发布版本。
- 每次发布都会生成一版快照并标记为已发布，之前发布的版本进入历史，可随时回看与恢复。
- 恢复旧版本不会抹掉历史：当前版本先归档为备份，目标版本被复制成一个**新的**已发布版本，旧记录仍然保留。
- 发布页可以选择呈现方式：**表单与结果**只展示输入、状态与最终结果，适合当作对外应用；**结果与详情**优先展示结果，并允许展开节点级执行轨迹，适合调试与内部排查。

### 运行状态对你的意义

| 你看到的状态 | 含义 | 该做什么 |
| --- | --- | --- |
| 排队中 | 已提交，还没轮到执行 | 稍等；长时间不动说明容量不足或执行服务不可用，联系运维，不要重复提交 |
| 运行中 | 节点正在依次执行 | 等待结果；需要中断时取消运行 |
| 等待审批 | 停在审批节点，等审批人提交反馈 | 打开运行详情提交意见；不提交就不会继续 |
| 已完成 | 有最终输出和每个节点的轨迹 | 结果可回看、可下载 |
| 失败 | 停在某个节点，详情给出该节点的错误 | 修正配置后重新运行 |
| 已取消 / 已超时 | 被主动取消，或超过运行时限 | 需要结果就重新运行 |

节点也有自己的状态：等待、运行中、完成、失败，以及**已跳过**（条件未命中的分支）。运行状态和节点状态含义不同，排查问题时看对应层级，不要混用。

### 等待审批

- 运行到达审批节点时整次暂停，停在「等待审批」，不会继续执行下游节点。
- 审批人提交反馈后，运行从暂停处继续，**已完成的节点不会重跑**，之前的模型调用与工具结果被复用。
- 可以要求所有审批人都同意才继续，也可以任一审批人同意即通过；任一审批人拒绝时运行结束。
- 审批表单的提示文案与需要填写的字段由工作流编排时设定，审批人看到的就是发起者要求的那些内容。
- 等待期间可以放心关闭页面，状态与待办都在运行记录里。

### 节点追踪

运行详情展示整次运行的输入、最终输出，以及每个节点的输入输出、状态、耗时、Token、错误与命中的分支。并行执行的分支会同时出现在轨迹里，用它可以判断一次运行是慢在某个节点、错在某个节点，还是某个条件走了另一条路。

- **注释节点**只用于画布说明，不参与执行，也不会出现在执行轨迹里。
- **迭代**与**循环**是容器节点，内部子图有独立的开始与结束：迭代按数组逐项执行，循环重复执行直到条件满足。循环次数有上限，超出会被强制终止。
- 节点与字段的完整说明见[工作流节点参考](/reference/workflow-nodes)。

### 两种开始方式

- **用户输入**：生成可交互的运行表单，适合人工发起。
- **触发器**：由外部调用、定时任务或 Webhook 启动，适合集成与自动化。

每个工作流只能有一个开始节点，且开始节点不能删除（在画布上删除会被拒绝并提示）。

### 历史工作流注意

<Callout type="warn">
早期定义的工作流在节点之间传递的是文本化数据，与当前的数据传递方式不兼容。打开历史工作流时请**先手动保存一次再运行**，否则可能拿到与预期不符的结果。发布前的检查清单会提示不存在的变量引用、缺失的必填输入与类型不匹配，运行前先处理这些提示。
</Callout>
