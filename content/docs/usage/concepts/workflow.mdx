工作流用有向节点图编排确定性的多步骤任务。开始节点定义输入，处理中间节点变换或调用能力，输出节点定义最终结果。

### 两种开始方式

- **用户输入**：生成可交互的运行表单，适合人工发起。
- **触发器**：通过手动/API、Webhook 或 Cron 启动，适合集成与自动化。

每个工作流只能有一个开始节点，且开始节点不能删除。

### 类型化数据流

当前定义格式为 `schema_version: 2`。节点输出保留原生对象与数组，不再隐式转为 JSON 字符串。旧版定义可以打开，但必须重新保存后才能运行。变量引用由编辑器的变量选择器完成；发布前检查清单会报告不存在的引用和类型不匹配。

### 节点与容器

节点分为模型、逻辑、转换和扩展四类。迭代遍历数组；循环重复执行直到条件满足；两者都是容器节点，内部子图有独立开始与退出节点。完整字段见[工作流节点参考](/reference/workflow-nodes)。

### 运行、调试与观测

草稿可以**调试运行**，已发布版本可以正式运行。执行状态包括等待中、运行中、成功、失败、已取消、超时与已跳过。运行抽屉展示输入、结果、节点追踪、Token、耗时、错误与匹配分支。

### 发布、版本与恢复

发布时自动创建版本快照。恢复旧版本会先保存当前状态，再把指定版本复制为新的当前版本，因此不会抹掉版本历史。发布页可选择**表单与结果**或**结果与详情**两种呈现模式。
