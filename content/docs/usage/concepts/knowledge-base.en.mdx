A Knowledge Base converts documents into chunks that Agents and Workflows can retrieve. The resource belongs to a team; you select an embedding model when creating it, and optionally a rerank model.

### Deep-Dive Retrieval & Ingestion Pipeline

```text
┌───────────────────────────┐     ┌────────────────────────────────────────────────────────┐
│ Uploaded Documents        │ ──► │ MarkItDown Multi-Format Parser                         │
│ (PDF, DOCX, XLSX, HTML...)│     │ • Base64 Embedded Media Extraction -> Asset Storage    │
└───────────────────────────┘     │ • Structure Flattening & XSS Sanitization (Bleach)     │
                                  └────────────────────────────────────────────────────────┘
                                                              │
                                                              ▼
                                  ┌────────────────────────────────────────────────────────┐
                                  │ Two-Stage CJK-Aware Chunking Engine                    │
                                  │ • Hard Boundary Split on Decoded Escapes (\n\n, \n)    │
                                  │ • Zero-Overlap Recursive Splitting + Trailing Overlap  │
                                  └────────────────────────────────────────────────────────┘
                                                              │
                                         ┌────────────────────┴────────────────────┐
                                         ▼                                         ▼
                          ┌──────────────────────────────┐          ┌──────────────────────────────┐
                          │ PostgreSQL 17 + pg_search    │          │ Qdrant Vector Engine         │
                          │ • BM25 Tantivy Lexical Index │          │ • Dense Embeddings ({prefix})│
                          └──────────────────────────────┘          └──────────────────────────────┘
                                         │                                         │
                                         └────────────────────┬────────────────────┘
                                                              ▼
                                  ┌────────────────────────────────────────────────────────┐
                                  │ Weighted Reciprocal Rank Fusion (RRF, k=60)            │
                                  │ • Channel Fault-Tolerance & Shared Vector Cache        │
                                  └────────────────────────────────────────────────────────┘
                                                              │
                                                              ▼
                                  ┌────────────────────────────────────────────────────────┐
                                  │ Optional Neural Reranker (Cross-Encoder Scoring)       │
                                  └────────────────────────────────────────────────────────┘
                                                              │
                                                              ▼
                                  ┌────────────────────────────────────────────────────────┐
                                  │ Context Assembly & Token Budget Guard                  │
                                  │ • Adjacent Chunk Window Expansion (expand_adjacent)    │
                                  │ • Per-Document Chunk Throttling & Token Truncation     │
                                  └────────────────────────────────────────────────────────┘
```

1. **Document Ingestion & Media Deconstruction**:
   - **Universal Format Support**: Uses `MarkItDown` to parse PDF, DOCX, PPTX, XLSX, HTML, CSV, TXT, MD, and JSON.
   - **Embedded Media Extraction (`replace_embedded_media_data_uris`)**: Automatically scans for base64 inline images, extracts payloads to dedicated asset storage (`/knowledge-bases/{kb_id}/documents/{doc_id}/media/{filename}`), and replaces them with clean URLs.
   - **Flattening & Sanitization**: CSV tables become Markdown pipes; JSON trees are flattened using dot notation; all text is sanitized via `bleach` to strip unsafe markup.
2. **CJK-Aware Chunking Implementation**:
   - User-defined separators are decoded into real control bytes (`\n\n`, `\n`) via `_decode_separator_escapes`.
   - Chunks are split with zero internal overlap using a punctuation hierarchy (`\n\n`, `\n`, `。`, `！`, `？`, `；`, `，`, ` `), then prepended with exact character-level trailing slices from preceding chunks for deterministic token boundaries.
3. **Dual-Engine Hybrid Retrieval & Weighted RRF**:
   - **Lexical**: PostgreSQL `pg_search` (BM25 Tantivy index).
   - **Dense Vector**: Qdrant vector collections partitioned as `{prefix}_{dimension}`.
- **Weighted RRF Formula**: Multi-channel Reciprocal Rank Fusion scoring (default `k = 60`, `dense_weight = 1.0`, `lexical_weight = 1.0`). Automatic single-channel fallback on transient engine failures.
4. **Cross-Encoder Neural Reranking**: Candidate chunks from RRF are rescored with deep semantic cross-encoders and filtered by `rerank_score_threshold`.
5. **Context Assembly & Window Expansion**:
   - **Adjacent Chunk Expansion (`expand_adjacent`)**: Fetches adjacent sibling chunks (`chunk_index - 1`, `chunk_index + 1`) to reconstruct coherent paragraphs.
   - **Token Budget Guard**: Strictly constrained by `context_token_budget` and `max_chunks_per_document`.

### Retrieval Lab

**Hit testing / Retrieval Lab** runs single-configuration tests or A/B comparisons, showing each result's rank and score at the vector, full-text, fusion, and rerank stages, and can apply local presets to production Knowledge Base settings.
