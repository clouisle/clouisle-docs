知识库把团队的文档变成一段段可被 Agent 和工作流检索的内容。它要回答两个问题：内容怎么进来，回答时怎么找到最相关的片段。这一页讲过程与设置带来的差别；精确字段、取值范围与默认值见[知识库设置参考](/reference/knowledge-settings)，操作步骤见[导入文档](../guides/knowledge/import-documents.mdx)。

### 从文档到可检索内容

```text
上传 → 解析 → 分块 → 向量化 → 检索（语义 + 关键词）→ 重排 → 交给模型
```

1. **解析**：PDF、DOCX、PPTX、XLSX、HTML、CSV、TXT、Markdown 与 JSON 都可以导入。文档内嵌的图片会被抽取成独立文件并以链接代替，表格转成结构化内容，页面的危险标记会被清除，避免内容体积膨胀或带进不安全元素。
2. **分块**：文本按结构切成片段，标题层级、表格与代码块优先保持完整；小表格整体保留，大表格按行切分并在每个片段重复表头，脱离原文也能读懂。片段会记录所属章节，方便回到出处。
3. **向量化**：每个片段用知识库选定的嵌入模型转成语义表示，检索时才能按「意思相近」匹配。嵌入模型在创建时选定、之后不能更改；向量维度在首批文档处理时固定，后续文档与查询必须一致，否则会报维度不匹配——要么重新处理，要么新建一个知识库。
4. **检索**：一次查询同时走两条路——语义（换个说法也能命中）与关键词（必须原词匹配）。混合模式会把两路结果合并成一份排序。
5. **重排**：绑定重排序模型后，排序靠前的候选再由更精确的模型打一次分，改善「内容相关但排得靠后」的情况。
6. **组装**：最终交给模型的内容受总长度预算与单文档片段数上限约束，避免一份长文档把其他相关片段挤掉。

<Callout type="info">
处理是异步的：文档上传后要经过解析与向量化才能参与检索，列表里会显示待处理、处理中、完成或失败。批量导入结束时会给发起人一条完成通知，可以先去处理别的事。
</Callout>

### 分块设置带来的可见差别

- **分块大小**：默认 `1000` 字符。调大，单个片段更完整，但容易混入无关内容、更快占满上下文；调小，命中更精准，但片段可能缺少完整语义，读不出答案。
- **分块重叠**：默认 `100` 字符。相邻片段共享一段上下文，避免关键句被切在边界上；重叠过大等于重复存储，检索时也更费预算。
- **按字符而不是 Token 计量**：界面显示的 Token 数只是估算，中文与英文的比例差异很大，按 Token 调参要留余量。
- **自定义分隔符**：填写后按你指定的边界硬切分；想让文档按空行分段，就要输入 `\n\n`，转义序列会被还原成真正的换行。
- **先预览再处理**：改策略后先看切分结果，确认后再处理。已处理的文档需要重新分块才会生效，手工编辑过的片段会被保留。

### 检索设置带来的可见差别

- **检索方式**：型号、错误码、专有名词、人名这类必须原词命中的查询，全文更稳；换了说法、跨语言、描述模糊的查询，语义更稳；不确定时用混合。
- **返回结果数**：默认 `5`。调大提高召回机会，也带来更多噪声和更长的上下文；调小更快更聚焦，但可能漏掉关键片段。
- **相似度阈值**：默认不过滤。调高只保留更像的结果，过高会直接漏召回。
- **重排序**：绑定重排序模型后默认开启。候选越多，越可能救回排在后面的相关内容，耗时和成本也更高；分数阈值用于过滤重排后的低分结果。
- **文档范围**：可以只在选定文档内检索，用来确认某份资料的说法。
- 多个知识库一起使用时，各库先各自召回，再汇总统一排序、只做一次重排，而不是逐库拼接结果。

精确默认值与取值范围见[知识库设置参考](/reference/knowledge-settings)。

### 混合检索与 A/B 对比

- **混合检索**补的是单一路径的盲区：关键词只管原词，语义只管意思相近。两路同时召回再合并，既能捞回「换了说法的正确结果」，也能保证「必须原词匹配的编号」不丢。某一路不可用时，检索会降级为另一路，并告诉你原因。
- **检索实验室**可以对同一个查询跑单套配置，或 A/B 两套配置对比，逐条查看结果在语义、关键词、合并、重排各阶段的排名与分数。确认哪套更好后，再把预设应用到生产设置。
- 对比分块策略时，先在预览里确认切分结果，再对已处理文档执行重新分块。分块调优的取舍见[知识库优化](../best-practices/kb-optimization.mdx)，参数与混合检索细节见[检索与质量调优](../guides/knowledge/retrieval.mdx)。

### 团队可见性与跨团队共享

- 知识库归属团队：团队成员按角色访问；设为私有的知识库只有创建者可见。
- **跨团队共享是只读的**：被共享的团队可以列出、查看与检索该知识库，但不能上传文档、修改设置或删除。写操作仍要求属于知识库所在的团队。
- 私有知识库不能共享，也不能共享给它所属的团队；重复共享会被拒绝。
