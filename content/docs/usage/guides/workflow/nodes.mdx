工作流编辑器注册了以下节点，按节点面板的四个分类组织。每个节点的精确输入输出字段和配置项以编辑器配置和[节点参考](/reference/workflow-nodes)为准。

| 类别 | 节点 |
| --- | --- |
| 模型 | LLM、媒体生成 |
| 逻辑 | 条件分支、问题分类、决策、迭代、循环、暂停 |
| 转换 | 代码执行、模板转换、文件转 URL、变量聚合、变量赋值、参数提取 |
| 扩展 | 子工作流、Agent、工具、知识库检索、回答 |
| 入口与画布辅助 | 开始（用户输入 / 触发器，创建时选择）、注释（静态说明贴纸，不参与执行） |

**面板中不存在的类型**：`http_request` 和 `document_extractor` 只有执行器、没有节点组件，只会出现在通过 API 提交的定义里；`iteration_exit` / `loop_exit` 是迭代/循环容器内的结束标记，没有独立执行器，不能当独立节点连接。

## 选择节点的原则

- 需要对话模型推理时使用 **LLM**；需要在若干选项或有序等级中挑一个、并拿到概率和置信度时使用**决策**；需要复用完整 Agent 行为时使用 **Agent**。
- 需要依据知识库回答时使用**知识库检索**，再把结果映射到 LLM 或输出。
- 需要调用已有 HTTP/MCP/代码能力时使用**工具**，不要在工作流中重复保存凭据。
- 需要处理每个数组项时用**迭代**；需要在条件满足前重复时用**循环**。
- 需要隔离可复用流程时用**子工作流**，配置输入输出映射和失败策略。

## 决策节点

决策节点是唯一会**返回概率**的节点：它把一份状态交给决策模型，模型只回答一个问题并返回选项/等级的概率分布与置信度，节点再按结果走分支。它不生成文本，因此路由结果不需要从模型输出里解析，也不会因为模型多写一句话而走错分支。完整的配置步骤和示例见[编排工作流 → 决策节点](./orchestrate.mdx#决策节点)。

### 与 LLM、问题分类器的区别

| 维度 | LLM | 问题分类器 | 决策 |
| --- | --- | --- | --- |
| 底层模型 | 对话模型 | 对话模型 | 决策模型（非生成式） |
| 输出 | 生成的文本 | 提示词要求的 JSON，再用正则解析 `category` | 结构化结果：选项/等级 + 概率分布 + 置信度 |
| 分支依据 | 文本内容 | 解析出的类别 | 概率最高的选项/等级 |
| 分支句柄 | 无 | 每个类别一个 | 每个选项/等级一个，另有兜底分支 |
| 不确定性处理 | 无 | 只有模型自报的 `confidence` 字段 | 置信度阈值 + 兜底分支 |
| 典型用途 | 生成、总结、改写 | 意图路由 | 处置决策、优先级判定、二元放行判断 |

选择建议：只要"选哪条路"取决于自然语言语义，而你又需要知道模型有多确定，就用决策节点；纯文本生成用 LLM；只有固定的几个类别且不关心概率时，问题分类器更轻。

### 三种问题类型

| 问题类型 | 界面标签 | 选项/等级数量 | 分支句柄 | 置信度 | 何时用 |
| --- | --- | --- | --- | --- | --- |
| `choice` | 选择一个选项 | 1–255 个唯一选项 | 每个选项一个，另加兜底分支 | 有 | 互斥的若干处置（退款 / 技术支持 / 账单 / 其他） |
| `score` | 按有序等级评分 | 2–10 个**有序**等级 | 每个等级一个，另加兜底分支 | 有 | 等级本身有序（低/中/高、P0–P3），且需要数值评分 |
| `noul` | 是 / 否概率判断 | 固定两个 | `yes`、`no`，另加兜底分支 | 无 | 单一二元判断：概率 ≥ `0.5` 走 `yes`，否则 `no` |

`noul` 不返回置信度，所以置信度阈值对它无效；需要"不确定就交人工"时改用 `choice` 或 `score`。

### 分支句柄、兜底与阈值

- 选项（`choice`）或等级（`score`）的文本就是画布上的输出句柄名；兜底句柄默认叫 `default`，可在**兜底分支**里改名。
- 改动选项文本时，只要个数不变，编辑器按位置重映射已有连线；改过个数的残留连线会被检查清单报为"已过期的输出句柄"，必须重新连接。
- **置信度阈值**（`0`–`1`，可留空）只在返回置信度**严格小于**阈值时把流程改道到兜底分支；等于阈值仍走模型选中的分支。阈值只影响路由，`answer` 始终是模型选中的选项/等级，`selected_handle` 才是实际走的分支。
- 不设阈值时，只有"没有解析出分支"才会走兜底。没有连接下游的兜底分支会让流程在该节点结束。
- 决策节点默认最多重试 2 次（1 秒起指数退避并带抖动）。

### 输出与失败

输出变量：`answer`（选中的选项/等级或 `yes`/`no`）、`selected_handle`（实际走的分支）、`usage`（Token 用量），并按类型追加 `choice` + `confidence` + `probabilities`、`score` + `confidence` + `probabilities`，或 `noul`。

失败时的表现：配置缺失或选项不合法在运行前就报 `validation_error`；模型返回的答案类型、选项或概率集合与配置不一致时报 `decision_result_missing`；模型未授权、被禁用、端点被白名单拦截、超时（默认 `60` 秒）或配额不足会报对应的供应商错误。

### 调试决策分支

- 检查清单逐项检查：未选择模型、输入状态为空、判断说明为空、选项/等级数量不足或超限、选项为空或重名、连线使用过期句柄。
- 运行追踪里用 `selected_handle` 看实际走了哪条分支，用 `confidence` 看是否被阈值改道，用 `probabilities` 判断该调阈值还是改判断说明。
- 决策节点是一次调用、一个结果，没有中间步骤，也没有断点或单步调试——只能整轮运行调试。

## 节点级失败

每个运行节点记录输入、输出、模型、Token、耗时、重试次数、错误类型和错误信息。HTTP、代码、MCP 和媒体节点应配置可接受的超时；对不可重试的副作用接口，避免无条件重复调用。
