工作流编辑器注册了以下节点，按节点面板的四个分类组织。每个节点的精确输入输出字段和配置项以编辑器配置和[节点参考](/reference/workflow-nodes)为准。

| 类别 | 节点 |
| --- | --- |
| 模型 | LLM、媒体生成 |
| 逻辑 | 条件分支、问题分类、决策、迭代、循环、暂停 |
| 转换 | 代码执行、模板转换、文件转 URL、变量聚合、变量赋值、参数提取 |
| 扩展 | 子工作流、Agent、工具、知识库检索、回答 |
| 入口与画布辅助 | 开始（用户输入 / 触发器，创建时选择）、注释（静态说明贴纸，不参与执行） |

**面板中不存在的节点**：HTTP 请求与文档提取只有执行逻辑、没有画布节点，只会出现在通过程序提交的定义里；迭代/循环容器内的“结束标记”也不是独立节点，不能单独连接。

## 选择节点的原则

- 需要对话模型推理时使用 **LLM**；需要在若干选项或有序等级中挑一个、并拿到概率和置信度时使用**决策**；需要复用完整 Agent 行为时使用 **Agent**。
- 需要依据知识库回答时使用**知识库检索**，再把结果映射到 LLM 或输出。
- 需要调用已有 HTTP/MCP/代码能力时使用**工具**，不要在工作流中重复保存凭据。
- 需要处理每个数组项时用**迭代**；需要在条件满足前重复时用**循环**。
- 需要隔离可复用流程时用**子工作流**，配置输入输出映射和失败策略。

## 决策节点

决策节点是唯一会**返回概率**的节点：它把一份状态交给决策模型，模型只回答一个问题并返回选项/等级的概率分布与置信度，节点再按结果走分支。它不生成文本，因此路由结果不需要从模型输出里解析，也不会因为模型多写一句话而走错分支。完整的配置步骤和示例见[编排工作流 → 决策节点](./orchestrate.mdx#决策节点)。

### 与 LLM、问题分类器的区别

| 维度 | LLM | 问题分类器 | 决策 |
| --- | --- | --- | --- |
| 底层模型 | 对话模型 | 对话模型 | 决策模型（非生成式） |
| 输出 | 生成的文本 | 提示词要求的 JSON，再解析类别 | 结构化结果：选项/等级 + 概率分布 + 置信度 |
| 分支依据 | 文本内容 | 解析出的类别 | 概率最高的选项/等级 |
| 分支句柄 | 无 | 每个类别一个 | 每个选项/等级一个，另有兜底分支 |
| 不确定性处理 | 无 | 只有模型自报的置信度字段 | 置信度阈值 + 兜底分支 |
| 典型用途 | 生成、总结、改写 | 意图路由 | 处置决策、优先级判定、二元放行判断 |

选择建议：只要“选哪条路”取决于自然语言语义，而你又需要知道模型有多确定，就用决策节点；纯文本生成用 LLM；只有固定的几个类别且不关心概率时，问题分类器更轻。

### 三种问题类型

| 问题类型 | 界面标签 | 选项/等级数量 | 分支句柄 | 置信度 | 何时用 |
| --- | --- | --- | --- | --- | --- |
| 选择一个选项 | 选择一个选项 | 1–255 个唯一选项 | 每个选项一个，另加兜底分支 | 有 | 互斥的若干处置（退款 / 技术支持 / 账单 / 其他） |
| 按有序等级评分 | 按有序等级评分 | 2–10 个**有序**等级 | 每个等级一个，另加兜底分支 | 有 | 等级本身有序（低/中/高、P0–P3），且需要数值评分 |
| 是 / 否判断 | 是 / 否概率判断 | 固定两个 | **是**、**否**，另加兜底分支 | 无 | 单一二元判断：概率不低于 `0.5` 走**是**，否则走**否** |

“是 / 否判断”不返回置信度，所以置信度阈值对它无效；需要“不确定就交人工”时改用“选择一个选项”或“按有序等级评分”。

### 分支句柄、兜底与阈值

- 选项或等级的文本就是画布上的输出句柄名；兜底句柄默认叫 `default`，可在**兜底分支**里改名。
- 改动选项文本时，只要个数不变，编辑器按位置重映射已有连线；改过个数的残留连线会被检查清单报为“已过期的输出句柄”，必须重新连接。
- **置信度阈值**（`0`–`1`，可留空）只在返回置信度**严格小于**阈值时把流程改道到兜底分支；等于阈值仍走模型选中的分支。阈值只影响路由：**判断结果**始终是模型选中的选项/等级，**实际分支**才是真正走的那条。
- 不设阈值时，只有“没有解析出分支”才会走兜底。没有连接下游的兜底分支会让流程在该节点结束。
- 决策节点默认最多重试 2 次（1 秒起指数退避）。

### 输出与失败

节点输出包括：判断结果（选中的选项/等级或“是/否”）、实际分支、Token 用量，以及按问题类型追加的置信度与概率分布。

失败时的表现：配置缺失或选项不合法在运行前就报校验错误；模型返回的答案类型、选项或概率集合与配置不一致时报结果不匹配；模型未授权、被禁用、地址被白名单拦截、超时（默认 `60` 秒）或配额不足会报对应的供应商错误。

### 调试决策分支

- 检查清单逐项检查：未选择模型、输入状态为空、判断说明为空、选项/等级数量不足或超限、选项为空或重名、连线使用过期句柄。
- 运行追踪里看实际分支（哪条路被走了）、置信度（是否被阈值改道）、概率分布（用于判断该调阈值还是改判断说明）。
- 决策节点是一次调用、一个结果，没有中间步骤，也没有断点或单步调试——只能整轮运行调试。

## 工具节点

工具节点执行内置工具、自定义 HTTP/代码/数据库工具、MCP 工具或 Skill。每个参数一条映射，来源可以是上游变量，也可以是常量。

- **常量要先声明类型**：界面里填的常量都是文本，映射的类型决定执行前的转换——整数、浮点、布尔、数组、对象分别按对应格式解析。所以 `"10"` 只有在声明为整数时才会变成数字。转换失败（非数字、非法 JSON）会让节点报参数无效，不会把错误类型悄悄传给工具。
- **网页搜索选引擎**：选中内置网页搜索时节点自动补一条引擎映射并显示下拉，默认项用站点默认，其余只列站点已启用的引擎；执行时还会重新校验，引擎被禁用会直接失败。
- **输出**：执行结果、状态（成功 / 失败）、耗时（毫秒），以及自定义的输出变量名。
- **权限**：私有工具只对创建者可用；跨团队工具必须在工作流所属团队获得共享，否则提示工具不存在。

完整字段见表：[工作流节点参考](/reference/workflow-nodes#工具节点-tool)。

## 暂停节点与审批

暂停节点把运行置为**等待**，直到有人处理请求：

- **变量模式**：等待成员填写声明的字段，提交后这些字段成为节点输出。
- **审批模式**：等待**通过** / **拒绝**决定，输出决定、是否通过、审批意见和提交人；拒绝会让运行以“审批被拒绝”失败。
- **审批人**：指定名单时只允许列出的团队成员提交（超级管理员可越过）；留空则回退到工作流创建者加团队管理员。
- **审批策略**：默认任一人提交即决定；开启**需要全员通过**后，每位审批人都要各自提交，全部通过才恢复，任一人拒绝立即失败，同一人重复提交会被拒绝。
- **说明模板**：支持 `{{变量}}`，保存前解析；解析不到的引用变成空字符串，不会把原始占位符展示给审批人。

运行页会在运行抽屉里实时展示节点轨迹（每个节点的状态、输入/输出与耗时），等待中的暂停请求也在同一抽屉内提交。审批接口见[工作流 API](/api/workflow)。

## 节点级失败

每个运行节点记录输入、输出、模型、Token、耗时、重试次数、错误类型和错误信息。HTTP、代码、MCP 和媒体节点应配置可接受的超时；对不可重试的副作用接口，避免无条件重复调用。
