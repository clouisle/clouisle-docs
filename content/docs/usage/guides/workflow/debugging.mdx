工作流问题分为配置问题、数据流问题和运行时问题。先检查清单，再调试运行，最后查看节点追踪和服务日志。

## 配置校验

**检查清单**会报告：未选择模型、工具或知识库，输入/输出无来源，变量引用不存在，条件分支不完整，代码或模板为空，迭代/循环缺少开始或处理节点，以及没有输出节点。

## 调试运行

选择**调试运行**并填入输入。调试运行使用草稿，不会改变已发布版本。运行抽屉的**详情**显示输入、输出和错误；**追踪**显示每个节点的状态、输入、输出、Token、耗时和重试次数。

## 运行状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 已创建，等待执行 |
| `running` | 正在执行 |
| `success` | 全部流程成功完成 |
| `failed` | 某节点或运行时失败 |
| `cancelled` | 用户取消 |
| `timeout` | 达到运行时限制 |
| `skipped` | 被条件或循环跳过 |

## 监控指标

工作流**监控**页按 `7d` 或 `30d` 展示总运行次数、成功率、平均耗时、失败次数、状态分布与运行趋势。运行日志支持按状态、时间和完整运行 ID筛选。

## 排查顺序

1. 检查输入变量是否存在且类型正确。
2. 查看第一个失败节点，而不是只看最终错误。
3. 对 LLM 检查模型授权、提示词和 Token；对 HTTP 检查 URL、请求头、超时与响应路径；对代码检查包版本、资源限制和产物路径。
4. 对知识库检查文档是否完成处理、嵌入维度是否匹配以及检索服务可用性。
5. 若是已发布应用，确认已发布版本而不是草稿编辑器。
