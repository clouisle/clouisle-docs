In **Knowledge Bases**, select a knowledge base to browse its documents: search by name, filter by processing status or file type, and select rows for batch actions. Open a document to inspect and edit its chunks, and to preview or download the original file. Knowledge bases shared in from another team carry an origin badge and are read-only throughout.

## Document List

Each row shows the document name, type, size, chunk count, processing status, and creation time, with a row menu offering:

| Action | Notes |
| --- | --- |
| **Configure** / **Quick Process** | Unprocessed documents only: **Configure** opens the detail page to adjust chunk parameters, while **Quick Process** starts processing with the current settings |
| **Manage Chunks** | Opens the document detail page to view and edit chunks |
| **Reprocess** | Opens chunk preview; confirm or adjust, then re-chunk and index again — manual chunk edits are lost |
| **Retry Failed Chunks** | Failed documents only: retries just the failed chunks |
| **Download Original** | Downloads the file as uploaded; URL imports have no original |
| **View Source URL** | URL imports only: opens the origin address |
| Delete | Deletes the document and all its chunks |

- **Search documents…** filters by name; the status filter (pending/processing/completed/failed) and the type filter each accept one value at a time.
- Select several rows to **Batch Process**, **Batch Retry Failed Chunks**, or delete them together.
- Documents uploaded but not yet chunk-configured are flagged at the top of the list; select the batch configuration action there to continue.
- Documents managed by Feishu sync carry a read-only marker: edit the original in Feishu, since local edits, reprocessing, and deletion are unavailable here.

## Document Detail Page

Chunks are listed on the left and chunk settings on the right.

- The chunk list shows each chunk's index and content; you can **Edit Chunks**, add a chunk, or delete one. If a chunk has unsaved changes, the editor asks whether to save or discard before leaving.
- When the status is failed, retry only the failed chunks instead of reprocessing the whole document.
- For an unprocessed document, adjust **Chunk Size** (in characters), **Chunk Overlap**, **Custom Separator**, and **Clean Text** on the right, then start processing. After processing completes, changing those settings requires **Reprocess**.
- **Preview Original** opens a read-only preview, described below.

### Original File Preview

Choose **Preview Original** to open the viewer on the right. The preview reads the protected original file and does not bypass chunk permissions; closing the viewer returns to the chunk list.

| File type | Preview capabilities |
| --- | --- |
| **PDF** | Page rendering, thumbnail sidebar, page jump, zoom, rotation, text search |
| **DOCX** | Paginated view, thumbnails, zoom, text search; comments and tracked changes |
| **PPTX** | Slide thumbnails, previous/next, page jump, zoom |
| **XLSX** | Read-only sheet-by-sheet view with column sorting, search, and cell inspection |
| **CSV** | Grid view and text search, with UTF-8 / GB18030 decoding fallback |
| **Image** | Original image display |
| **HTML / Markdown / text** | Read-only text or rendered output |

- Files over **`20MB`** are not previewed online; download the original and open it locally.
- Viewers load on demand: a component is fetched only the first time that file type is opened, so the document list stays light.
- Search, zoom, download, and close controls follow the UI language; dark mode follows the site theme.
- Missing view/download permission, signed-out state, unsupported types, and parse failures produce a specific reason instead of a blank panel.
- URL imports have no original file, so only the source address and chunks are available.

When the preview cannot open, it names the reason: file too large, your account lacks view/download permission, not signed in, unsupported type, or parse failure. Retry after fixing permission or sign-in problems; format problems require downloading the file.

## Document Information and Automatic Metadata

The header shows the document name, its knowledge base, file size, chunk count, and processing status; URL documents show the source address.

The system also records information automatically for every document and chunk: the document's format (whether it was converted to Markdown), its character count, the embedded images extracted from it, and each chunk's section (for example `Chapter 1 > Section 2`) and chunk type (table/code/list/text). These values are read-only and recomputed on reprocessing, with no field-by-field editing in the interface; they travel with search results so answers can cite their source.

## Sharing Origin and Read-Only Scope

| Badge | Shown when | Meaning |
| --- | --- | --- |
| **From `{team}`** | The knowledge base belongs to another team and is shared with yours | Read-only: upload, import, chunk editing, delete, and settings entry points are all unavailable |
| **Shared with `{N}` teams** | Your team owns it and has shared it with N teams | You can still read and write normally |

Cross-team sharing, read-only semantics, and how to revoke are covered in [Create a Knowledge Base](./create-knowledge-base.mdx).

## Renaming and Other Limits

- The interface has no document rename entry point; the name can only be updated through the API — see the [Knowledge Base API](../../../api/knowledge.mdx#update-document) for the field.
- Tags, categories, folders, and field-level metadata editing are not implemented.
- Search cannot filter or boost by metadata; results can only be limited to specific documents. See [Retrieval & Quality Tuning](./retrieval.mdx) for the supported knobs.
- Images extracted from chunks have no public link and require a signed-in session.
