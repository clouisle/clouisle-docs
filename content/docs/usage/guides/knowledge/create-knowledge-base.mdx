知识库必须归属于一个团队。创建时选择的嵌入模型决定向量维度；文档首次处理后不应更换嵌入模型，若必须更换，需要重建索引。

## 创建知识库

1. 前往**知识库**，选择**创建知识库**。
2. 填写基本信息：
   - **名称**：`1-100` 字符，用于知识库列表展示。
   - **描述**：最多 `500` 字符，说明知识库用途和内容范围。
   - **团队**：选择知识库归属的团队。
3. 选择模型：
   - **嵌入模型**：选择团队已授权的 `embedding` 模型，或使用平台默认配置。`embedding_model_id` 创建后不可更改。
   - **重排序模型**：可选，选择 `rerank` 模型以提升检索精度。
4. 配置分块与检索设置：
   - **分块大小**：每个分块的字符数，默认 `1000`，最小 `100`。
   - **分块重叠**：相邻分块之间的重叠字符数，默认 `100`，最小 `0`。
   - **分隔符**：自定义文本分隔符（可选）。
   - **检索模式**：`vector`、`fulltext` 或 `hybrid`（默认 `hybrid`）。
   - **重排序**：启用重排序以优化检索结果。
5. 点击**创建知识库**。
6. 打开知识库详情，确认状态为**启用**。

</Callout>

## 嵌入与重排序模型

嵌入模型是平台上 `model_type = embedding` 的常规模型（如 OpenAI `text-embedding-3-small` 或兼容的本地模型），通过模型授权分配给团队。每个知识库引用一个嵌入模型（`embedding_model_id`）和一个可选的重排序模型（`rerank_model_id`）。

### 嵌入模型锁定

由于已存储的向量依赖于创建时选择的嵌入模型，因此创建后嵌入模型即被锁定。管理员编辑表单不允许修改 `embedding_model_id`，尝试更新会被拒绝。如需更换嵌入模型，必须创建新的知识库并使用新模型处理文档。

## 文档管理

文档管理包括上传、处理、重新处理和删除。详细操作见[导入文档](./import-documents.mdx)和[分块与文档处理](./chunking.mdx)。

### 上传文档

- **单个上传**：选择知识库 → **上传文档** → 选择文件 → **上传**。上传通过 `POST /api/v1/knowledge-bases/{kb_id}/documents/upload`（multipart）完成，上传后文档状态为 `pending`，不会自动开始提取或嵌入。
- **批量操作**：在文档表格中选择多个文档，可对等待中文档执行**快速处理**、对失败文档执行**重试失败分段**或**删除**。
- **支持格式**：PDF、DOC/DOCX、TXT、Markdown、HTML、CSV、XLS/XLSX、PPT/PPTX、JSON、URL。

<Callout type="warn">
  上传文档与处理文档是两个阶段。文档出现在列表中不代表已经完成嵌入；只有状态为**已完成**才适合绑定到 Agent。
</Callout>

### 文档处理流程

```
上传 → 提取文本 → 清理 → 分块 → 生成嵌入 → 索引
```

**处理状态：**
- **等待中**：已上传，等待管理员启动处理。
- **处理中**：正在提取、分块、嵌入或索引。
- **已完成**：成功索引，可参与检索。
- **错误**：处理出错，查看错误信息后重试或重新处理。

### 重新处理文档

- **单个重新处理**：选择已完成或错误的文档 → **重新处理** → 预览分块 → **处理**。
- **重试失败分段**：选择错误文档 → **重试失败分段**。
- 批量重新处理通过选择工具栏对等待中文档执行快速处理或对失败文档执行重试。

### 删除文档

- **单个删除**：选择文档 → **删除** → 确认。
- **批量删除**：选择多个文档 → **批量删除** → 确认。

## 检索配置

检索在知识库设置中按知识库配置。详细字段说明见[知识库设置参考](/reference/knowledge-settings.mdx)，检索效果比较见[检索与质量调优](./retrieval.mdx)。

### 检索模式

| 模式 | 说明 |
| --- | --- |
| `vector` | 纯向量检索，基于语义相似度 |
| `fulltext` | 全文检索，基于关键词匹配 |
| `hybrid` | 混合检索，融合向量与全文结果（默认） |

### 混合检索参数

- **稠密权重**：向量检索的 RRF 权重，默认 `1.0`。
- **词法权重**：全文检索的 RRF 权重，默认 `1.0`。
- **RRF K**：倒数排名融合参数，默认 `60`，范围 `1-1000`。
- 稠密权重或词法权重至少一个必须大于 `0`。

### 重排序

- **启用重排序**：开启后对检索结果进行重排序以提升精度。
- **候选池大小**：`1-100`，默认 `10`。
- **分数阈值**：可选，`0-1`。

### 测试检索

1. 选择知识库 → **命中测试**。
2. 输入 `1-1000` 字符查询。
3. 选择检索方式、Top K（`1-20`，默认 `5`）、分数阈值（`0-1`，默认 `0`）和权重。
4. 查看匹配分块、相关度分数和来源文档。
5. 保存预设后可**应用到生产**。

## 统计与监控

### 知识库统计

`GET /api/v1/knowledge-bases/{kb_id}/stats` 返回每个知识库的统计数据：

- 文档总数
- 分块总数
- 嵌入总数
- 各处理状态计数
- 嵌入配置和向量维度

查看方式：选择知识库 → **统计**标签页。

## 故障排除

### 文档处理失败

- **症状**：文档状态为"失败"，日志中有错误信息。
- **解决方案**：
  1. 检查文件格式是否支持、文件是否损坏、文件大小是否超限。
  2. 查看处理日志：知识库 → 文档 → 选择文档 → 查看处理日志。
  3. 常见错误：
     - **文本提取失败**：文件损坏或格式不支持。
     - **分块失败**：分块设置无效。
     - **嵌入失败**：API 密钥无效或配额不足。
     - **索引失败**：Qdrant 连接问题。
  4. 重试处理：选择失败文档 → **重试** → 可选调整设置 → 确认。

### 检索无结果

- **症状**：检索返回空结果、找不到相关文档、检索报错。
- **解决方案**：
  1. 检查文档是否已完成索引，是否有索引错误。
  2. 使用**命中测试**验证检索结果和分数。
  3. 检查检索设置：分数阈值是否过高、Top K 值、尝试不同检索模式。
  4. 检查 Qdrant 服务是否健康可达。
  5. 必要时重新索引。

### 嵌入成本过高

- **症状**：意外高成本、触发成本告警。
- **解决方案**：
  1. 查看知识库统计中的嵌入使用量，定位高用量知识库。
  2. 优化分块：增大分块大小、减少重叠、过滤不必要内容。
  3. 使用更经济的模型（如 `text-embedding-3-small`）。
  4. 移除或重新处理不必要的文档。

<Callout type="info">
  未实现 / Roadmap：每知识库文档限制、每日嵌入配额和成本告警暂不可用。
</Callout>

### 检索性能慢

- **症状**：检索耗时过长、超时。
- **解决方案**：
  1. 查看统计中的检索性能，定位慢查询。
  2. 优化检索：减少 Top K、对简单查询禁用重排序、使用过滤器。
  3. 检查 Qdrant 资源使用（CPU/内存）和索引。
  4. 在基础设施层面增加资源或添加副本。

## 最佳实践

### 文档管理

- ✅ 使用描述性文档名称，按类别和标签组织文档。
- ✅ 添加元数据以提升检索效果，定期移除过时文档。
- ✅ 上传后监控处理状态，测试检索结果。
- ❌ 不要上传重复文档，不要使用不清晰的文件名。
- ❌ 不要忽略处理错误，不要忘记测试检索。

### 分块策略

- ✅ 根据内容类型选择合适分块大小：叙述性内容使用语义分块，结构化数据使用固定分块。
- ✅ 测试不同策略，监控分块质量，根据检索性能调整。
- ❌ 不要对所有内容使用同一策略，分块不宜过大或过小。
- ❌ 不要忽略分块重叠，不要跳过测试。

### 检索优化

- ✅ 使用混合检索获得最佳结果，启用重排序提升精度。
- ✅ 设置合适的分数阈值，监控检索性能，收集用户反馈。
- ❌ 不要仅依赖向量检索，阈值不要设置过高。
- ❌ 不要忽略性能指标和用户反馈。

## 批量操作

文档表格支持基于选择的操作：

- **快速处理**：处理选中的等待中文档。
- **重试失败分段**：重试选中的失败文档。
- **删除**：删除选中的文档。

不支持 ZIP/多文件批量上传或批量元数据更新。文件需单独上传，然后使用预览/编辑器或选择工具栏进行处理。

## API 访问

通过 API 管理知识库，详见 [Knowledge Bases API](/en/api-reference/endpoints/knowledge-bases)。

**常用操作：**

```python
# 列出知识库 — 过滤：team_id、search、status、own_only
kbs = api.get("/api/v1/knowledge-bases", params={"team_id": "team-123"})

# 为团队创建知识库
kb = api.post("/api/v1/knowledge-bases", json={
    "name": "Product Docs",
    "team_id": "team-123",
    "embedding_model_id": "model-456",
    "settings": {"chunk_size": 1000, "chunk_overlap": 100, "search_mode": "hybrid"}
})

# 上传文档
with open("document.pdf", "rb") as f:
    doc = api.post(
        f"/api/v1/knowledge-bases/{kb_id}/documents/upload",
        files={"file": f}
    )

# 检索知识库
results = api.post(f"/api/v1/knowledge-bases/{kb_id}/search", json={
    "query": "How to reset password?",
    "top_k": 5
})
```

**文档处理 API：**

| 端点 | 说明 |
| --- | --- |
| `POST /api/v1/knowledge-bases/{kb_id}/documents/{doc_id}/process` | 处理等待中的文档 |
| `POST /api/v1/knowledge-bases/{kb_id}/documents/{doc_id}/process-with-chunks` | 使用指定分块设置处理 |
| `POST /api/v1/knowledge-bases/{kb_id}/documents/{doc_id}/reprocess` | 重新处理文档 |
| `POST /api/v1/knowledge-bases/{kb_id}/documents/{doc_id}/rechunk` | 重新分块文档 |
| `POST /api/v1/knowledge-bases/{kb_id}/documents/{doc_id}/retry-failed-chunks` | 重试失败分段 |
| `POST /api/v1/knowledge-bases/{kb_id}/documents/{doc_id}/chunks/{chunk_id}/retry-embedding` | 重试单个分块嵌入 |
