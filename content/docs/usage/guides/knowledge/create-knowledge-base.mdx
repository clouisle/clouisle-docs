知识库必须归属于一个团队。创建时的两个决定最难回头：**嵌入模型决定向量维度**（文档处理后不可更换），**可见性决定谁能在没有共享的情况下读到它**。名称在团队内必须唯一。

<Callout type="info" title="前置条件">
  1）你是目标团队的成员，并拥有创建知识库的权限；2）团队已获授权一个可用的嵌入模型（未授权会在创建时被拒绝，缺少可用模型则该知识库无法检索）；3）如需重排序，再授权一个重排序模型。授权与供应商配置见[模型管理](../models/manage-models.mdx)。
</Callout>

## 权限与可见性

| 操作 | 谁可以做 |
| --- | --- |
| 查看知识库 / 文档 / 分块 | 团队成员，且符合可见性规则 |
| 命中测试（检索） | 有查看权限的人 |
| 创建知识库 | 团队成员 |
| 编辑设置、上传/处理/删除文档、编辑分块 | 创建者本人，或团队管理员 |
| 删除知识库 | 团队管理员 |
| 共享给其他团队 / 取消共享 | 所属团队管理员 |

可见性在创建/编辑对话框中设置：

| 可见性 | 谁可以读 | 说明 |
| --- | --- | --- |
| **私有** | 仅创建者 | 团队其他成员看不到；**不能共享给其他团队** |
| **团队** | 本团队所有成员 | 写入仍需要创建者或团队管理员 |
| 公开 | 预留值 | 界面不提供，仅作兼容保留 |

跨团队访问只能通过共享获得，且始终是只读的——见下文「跨团队共享（只读）」。

## 知识库列表

管理员在**管理后台** → **知识库**看到的是跨团队的知识库表格：

| 表格列 | 说明 |
| --- | --- |
| **名称** | 知识库名称，描述显示为第二行 |
| **团队** | 所属团队 |
| **文档数** | 文档总数 |
| **分块数** | 分块总数 |
| **状态** | 当前状态 |
| **创建时间** | 创建时间 |

表格另有行选择框与每行的操作入口。列表只提供**启用 ↔ 归档**的状态切换；筛选面的状态选项只有**启用**与**归档**。

列表还支持按团队、名称关键词和状态筛选；接收共享的团队可以选择只看自己团队的知识库。

## 创建知识库

1. 前往**知识库**，选择**创建知识库**。
2. 填写基本信息：
   - **名称**：`1-100` 字符，**团队内唯一**，重名会报错。
   - **描述**：最多 `500` 字符，说明用途与内容范围。
   - **团队**：使用当前团队（管理后台的创建表单可指定其他团队）。
3. 选择模型：
   - **嵌入模型**：团队已授权的嵌入模型。创建后不可更改。
   - **重排序模型**：可选，绑定后可在检索时对召回结果二次打分。
4. 配置分块与重排序：
   - **分块大小**：默认 `1000` 字符，最小 `100`（界面建议上限 `2000`）。
   - **分块重叠**：默认 `100` 字符，最小 `0`（界面建议上限 `500`）。
   - **自定义分隔符**：可填 `\n\n` 等转义写法，作为硬切分边界。
   - **启用重排序**：默认开启；**重排序候选数** 默认 `10`（`1-100`）；**重排序分数阈值** 默认留空（`0-1`）。
5. 选择**可见性**（**私有**或**团队**）。
6. 点击**创建知识库**，随后进入知识库详情页；确认状态为**启用**。

编辑已有知识库时，对话框额外提供**启用知识库**开关（关闭即归档，归档后的知识库不参与检索）。

</Callout>

## 模型与向量维度

### 嵌入模型

嵌入模型在平台登记并授权给团队后，才会出现在创建表单中。知识库只引用一个嵌入模型；没有可用模型时，文档处理与检索都无法进行。

### 向量维度

向量维度在**首批文档完成向量化时写入**并固化。此后：

- 维度一致的文档正常入库；
- 维度不一致的向量会写入失败，检索时界面会提示核对模型与索引维度；
- 更换嵌入模型不会自动重建索引，需要新建知识库或执行完整的重新处理流程。

## 分块与检索设置

创建对话框和知识库设置里的关键项如下，字段级定义与全部限制见[知识库设置参考](/reference/knowledge-settings)：

| 设置 | 默认值 | 范围 | 生效位置 |
| --- | --- | --- | --- |
| 分块大小 | `1000` | `>=100` 字符 | 文档处理（下次处理/重新处理时生效） |
| 分块重叠 | `100` | `>=0` 字符 | 文档处理 |
| 自定义分隔符 | 空 | 任意字符串 | 文档处理，硬切分边界 |
| 启用重排序 | 开启 | 开/关 | 检索（需绑定重排序模型） |
| 重排序候选数 | `10` | `1-100` | 检索 |
| 重排序分数阈值 | 空 | `0-1` | 检索 |
| 检索方式 | 空 | 向量 / 全文 / 混合 | Agent/工作流检索的默认模式 |
| 返回结果数 | 空 | `1-100` | Agent/工作流检索 |
| 相似度阈值 | 空 | `0-1` | Agent/工作流检索 |

<Callout type="warn" title="知识库设置与检索请求是两套默认值">
  知识库设置里的检索类字段默认是**空的**，只有显式设置后才生效；而**检索请求**不传参时按混合检索、返回 `5` 条、阈值 `0` 执行。命中测试面板会用知识库设置初始化，并可通过**应用到生产**把配置写回知识库。因此「知识库设置里的模式」主要影响 Agent/工作流检索，见[检索与质量调优](./retrieval.mdx)。
</Callout>

分块的字符语义、Markdown 与纯文本差异、预览与失败重试见[分块与文档处理](./chunking.mdx)。

## 跨团队共享（只读）

共享让**其他团队**获得对某个知识库的读取与检索能力，但**不能编辑**。这是唯一一种跨团队访问方式。

### 操作步骤

1. 在**知识库**列表中，把鼠标移到知识库卡片上，打开右上角 **⋯** 菜单，选择**共享**。
   - 该入口只对「自己团队拥有」的知识库显示，且需要团队管理员角色。
2. 在**共享**对话框中选择**团队**。
   - 候选列表来自你加入的团队，并自动排除当前团队与已共享过的团队。
   - **权限级别**只有**只读**一个选项且不可修改。
3. 点击**共享**。列表出现该团队、只读徽章与「由某人共享」的说明。
4. 需要撤销时，在**已共享给**列表中点击该条目的删除图标并确认，对方团队的列表会立即移除该知识库。

### 规则与失败原因

| 规则 | 结果 |
| --- | --- |
| **私有**可见性的知识库 | 不能共享，界面提示私有知识库不可共享 |
| 共享给本团队 | 拒绝，并提示不能共享给本团队 |
| 重复共享同一个团队 | 拒绝，并提示已共享过 |
| 接收方团队看到的共享 | 只有可见性为**团队**或公开的知识库 |
| 接收方权限 | 仅只读：可查看、检索、在 Agent/工作流中关联；不能改设置、上传、处理或删除文档 |
| 撤销一个不存在的共享 | 提示共享不存在 |

共享后在双方列表上的标识：

- 接收方：**来自** + 团队名的徽章，进入详情后所有写入入口禁用。
- 拥有方：**已共享 N 个团队** 徽章。

### 在 Agent 与工作流中使用共享库

- 接收团队的 Agent 只能关联**已共享给该团队**的知识库；未共享的知识库不会出现在选择列表中。
- 关联后可继续为该关联单独设置返回结果数、相似度阈值和检索方式，它们覆盖知识库默认值；共享本身不改变这些覆盖规则。
- 共享是只读的：接收方可以检索、命中测试、在 Agent/工作流中引用，但不能上传、处理、删除文档或编辑分块；检索按调用者身份与团队权限执行。

## 文档管理

文档管理包括上传、处理、重新处理和删除，详细步骤见[导入文档](./import-documents.mdx)与[分块与文档处理](./chunking.mdx)。

| 能力 | 说明 |
| --- | --- |
| 上传 | 上传后为**待处理**，不会自动处理 |
| URL 导入 | 通过安全校验后创建网址文档，进入预览页后由你确认分块 |
| 支持格式 | PDF、DOC/DOCX、PPTX、TXT、Markdown、HTML、CSV、XLS/XLSX、JSON、URL（不支持 `.ppt`、压缩包与 OCR） |
| 批量操作 | 勾选多个文档：等待中文档**快速处理**、失败文档**重试失败分段**、**删除** |
| 单文件上限 | 站点设置的文档上传上限，默认 `50MB`，范围 `1-1024MB` |

<Callout type="warn">
  上传与处理是两个阶段：文档出现在列表中不代表已经完成嵌入。只有**已完成**的文档能被检索，也才适合绑定到 Agent。
</Callout>

### 批量处理的完成通知与恢复入口

- 勾选多个待处理文档做批量处理，或从预览页批量提交分块时，**全部文档结束后只发一条汇总通知**，而不是每个文档一条。
- 通知受站点通知类型控制：全部成功发索引完成通知，全部失败发失败通知，部分成功优先按失败提醒（若失败类型被关闭则回退到成功类型）；两类都关闭时不发通知。通知链接指向该知识库。
- 知识库详情页顶部会出现**待处理文档**横幅（仅知识库创建者或所属团队管理员可见、可关闭；共享库不显示）。点击**继续处理**会一次性拉取该库的全部待处理文档并跳到预览页，离开页面后也能从这里接着做。

## 统计

知识库详情页顶部显示统计卡片（文档数、分块数、Token 数、各状态计数）；下拉菜单中的**命中测试**进入检索实验室。

- 文档数按实际文档重新计算，不使用缓存值。
- 分块数、Token 数按文档汇总并回写知识库统计。
- 统计还包含各状态、各类型的文档数量，以及嵌入维度与嵌入统计。

<Callout type="info">
  未实现 / Roadmap：查询量、响应时间、缓存命中率、热门查询等检索分析，存储使用趋势与统计导出均不可用。
</Callout>

## 故障排除

### 文档处理失败

1. 确认文件格式受支持、文件未损坏、大小未超限。
2. 打开文档详情查看错误信息，确认是提取、切分还是嵌入阶段失败。
3. 常见原因与处理：

| 原因 | 处理方式 |
| --- | --- |
| 文本提取失败（损坏、加密、纯图片） | 转换格式或解除密码后重新上传 |
| 分块为零 | 确认文件含可提取文本，或关闭文本清理后重试 |
| 嵌入失败（凭据、配额、维度） | 核对模型授权与向量维度，再重试失败分段 |
| 索引失败 | 联系管理员检查检索服务状态 |

### 检索无结果或结果无关

1. 确认文档状态为**已完成**。
2. 用**命中测试**验证分数：0 条结果时先降低相似度阈值，再切换检索模式。
3. 检查 Agent 是否为该知识库覆盖了返回结果数、阈值或检索方式。
4. 联系管理员检查检索服务是否健康；必要时重新处理文档。

### 成本或性能异常

- 成本偏高：减少不必要的重新处理，优化分块（更大的分块、更少的重叠），换用更经济的嵌入模型，删除冗余文档。
- 检索慢：降低返回结果数、对简单查询关闭重排序、缩小文档范围，并联系管理员检查检索服务资源。

<Callout type="info">
  未实现 / Roadmap：每知识库文档上限、每日嵌入配额与成本告警均不可用。
</Callout>

## 最佳实践

- ✅ 名称写清楚内容范围，避免「文档」「资料」这类无信息量的名字。
- ✅ 先用默认分块（`1000`/`100`）跑通一条代表性文档，再用命中测试对比调整。
- ✅ 定期清理过期文档；重复内容会互相竞争排名。
- ✅ 私有知识库只用于个人草稿；团队共用的内容用**团队**可见性。
- ❌ 不要指望手工「添加元数据」提升检索——元数据由处理流程自动生成，没有编辑入口。
- ❌ 不要在生产环境直接更换嵌入模型，也不要跳过检索验证直接放大分块。
