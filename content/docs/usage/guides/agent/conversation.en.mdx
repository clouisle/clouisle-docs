A published Agent has a full chat page; the editor's right-hand preview is for debugging while building. A conversation is created when the first message is sent and stores variables, message count, and token usage.

<Callout type="info">
  There is no global **Conversations** page or **New chat** selector. Each Agent's chat page only contains that Agent's recent conversations.
</Callout>

## Starting a Conversation

### From the Apps page

1. Go to **Apps** (`/app/apps`).
2. Select the **Agent** tab and find the Agent you want.
3. Open the Agent card menu and select **Chat**.
4. The Agent chat page opens at `/chat/{agent_id}`; sending the first message creates the conversation.

### Continuing from an existing chat page

1. Open the Agent's chat page.
2. Use the conversation controls on that page to continue the latest conversation or start a new one.
3. Type a message and send it.

## The Chat Interface

### Layout

```

│  Agent name                    [Settings] [...]  │
├─────────────────────────────────────────────────┤
│                                                  │
│  Agent: Hello! How can I help?                   │
│                                                  │
│  You: What is Clouisle?                          │
│                                                  │

│  [Sources: doc1.pdf, doc2.md]                    │
│                                                  │
├─────────────────────────────────────────────────┤
│  [📎] Type a message...          [Send]          │
└─────────────────────────────────────────────────┘
```

### Key elements

| Element | Description |
| --- | --- |
| **Agent name** | The Agent in this conversation |
| **Message history** | The scrollable conversation history |
| **Input box** | Where you type messages |
| **Attach button** | Upload files (available when the Agent enables attachments) |
| **Send button** | Send the message |
| **Stop button** | Interrupt a streaming reply |
| **Sources** | Reference documents from knowledge base retrieval (shown when a knowledge base is attached); click one to view the matching chunk in the preview panel |
| **Artifact list** | Files generated in that turn, shown below the assistant message body |
| **Preview panel** | Right-hand panel opened by clicking an artifact, image, or source; resizable on desktop, full-screen on mobile |

## Sending Messages

### Text messages

**Basic message:**
1. Type the message in the input box
2. Press **Enter** or click **Send**
3. Wait for the Agent to reply (streaming)

**Multi-line message:**
1. Type the message
2. Press **Shift+Enter** for a new line
3. Press **Enter** to send

### File uploads

If the Agent enables attachments:

1. Click the **📎 Attach** button
2. Choose files from your computer
3. Supported formats depend on the Agent configuration (PDF, DOCX, TXT, MD, CSV, XLSX, PPTX, images, …)
4. Wait for the upload/parsing to finish
5. Add a question about the file
6. Click **Send**

**Upload limits:**
- Every chat upload is capped at **10 MB** per file (enforced server-side)
- The maximum files per message is set by the Agent configuration (default 5)

See [Attachments and media](./media) for supported formats and security details.

## Understanding Replies

### Streaming

The Agent streams its reply in real time:
- Text appears word by word, readable while the Agent is still generating
- Click **Stop** to interrupt generation

### Reply anatomy

A reply may contain:

- **Body**: streamed in increments.
- **Reasoning**: shown only when the model provides it and the Agent does not hide it.
- **Reference documents**: retrieved chunks, document names, and relevance.
- **Tool calls**: arguments, results, logs, and artifacts; the Agent may hide the details.
- **Media results**: images or videos rendered directly in the assistant body.
- **Message action bar**: copy, versions, tokens, speed, and more; the Agent may hide it.

### Thinking timeline and source citations

Progress appears in the order it actually happens. Retrieval, context compression, reasoning, tool calls, media results, and the body may interleave; the UI does not force retrieval to the front.


<figure>
  <img src="/images/agent-chat-thought-trace.png" alt="Thinking timeline and tool calls in chat" />
  <figcaption>Thinking timeline: retrieval, tool calls, and artifacts in the order they happened</figcaption>
</figure>

Source markers in the reply follow the sentence they support; the **source list shows only sources actually cited**, and markers that cannot be matched to a known source are not rendered as numbers. With the Agent's **Citations** switch off, neither markers nor the source list appear; the Agent only produces citations when it has knowledge base retrieval, attachments, or web tools.

### Interactive questions

When the Agent enables **Interactive questions** (off by default) under **Orchestration**, the model can pause mid-reply and ask instead of guessing missing information.

1. The model asks, and the current run enters a waiting state with the input box disabled.
2. The form appears above the input box but is **not written into message history**; one interaction may contain `1-20` questions, paged one at a time. Option questions can be picked directly, free text is allowed, and optional questions can be left blank.
3. After you submit, the same run resumes from the pause point, and the questions and answers appear as tool steps in the run trace.
4. You can also **skip** the whole interaction and let the model continue with what it has.

Limits: each question is at most `2000` characters, with up to `50` options of at most `500` characters each. Answers are consumed once: resubmitting the same interaction produces no second result. Pending questions are stored with the run, so refreshing the page or switching back to the conversation restores the form — **do not rely on a refresh to cancel a question**; submit or click stop instead.

### Tool confirmation

When the team sets a tool to **Require caller confirmation**, the run pauses before executing it:

<figure>
  <img src="/images/chat-tool-confirmation.png" alt="Tool confirmation card in chat" />
  <figcaption>Confirmation card: tool name, description, redacted action details, and Allow / Decline</figcaption>
</figure>

1. A **Confirm this action** card appears above the composer with the tool name, description, and **View action details**; sensitive arguments are redacted.
2. Choose **Allow** to execute this call, or **Decline** to cancel it.
3. When several tools pause together, confirm each call independently; they resume in order.

Only **the user who started the run** can decide; team members, team administrators, and superusers cannot decide on their behalf. Refreshing or returning to the conversation restores the pending card — do not refresh to cancel; decline or stop the run. Stopping a waiting run cancels the pending confirmation. Runs started with an API key can only be decided by that same key; in Feishu/WeChat, send `/approve <execution UUID>` or `/reject <execution UUID>`. Workflows never prompt for confirmation.

For policies, legacy configuration, and audit records, see [Tool Approvals and Caller Confirmation](../tools/tool-approvals.mdx).

### Reply quality

**A good reply:**
- Answers the question directly
- Includes relevant context and detail
- Cites sources (when using a knowledge base)
- Is clearly structured and formatted

**If the reply is poor:**
- Restate the question more clearly
- Provide more context
- Split complex questions into simpler parts
- Check whether the Agent has the relevant knowledge base

## Attachments and Media

Attachments give the Agent user-uploaded documents and images; media generation lets the Agent call authorized image or video models. Both must be enabled in the Agent **orchestration** area.

Default attachment limits: `10 MB` per file (`1KB-50MB`) and `5` files per message (`1-10`). Images only enter the model directly when the chat model supports vision.

See [Attachments and media](./media) for configuration.

## Variables and Forms

If the Agent defines required variables, complete the variable form before sending. Variables are referenced in the prompt as `{variable_name}`; `{query}` is the current user message.

1. The variable form appears at the top of the chat page
2. Fill in the required fields
3. Type a message and send it

## Stopping, Steering, and Regenerating

- **Stop**: clicking **Stop** during streaming ends the current reply immediately, and the message is marked as manually stopped.
- **Steering (User Guidance)**: while the Agent is streaming or reasoning, you can send clarifying or corrective input without stopping. A floating capsule above the input box shows the queued guidance; it is injected into the current turn's context and appears as a “User Guidance” step in the thinking timeline.
- **Edit**: editing a past user message creates a new branch from that point and streams a new reply with that context.
- **Regenerate**: regenerating an assistant message creates a new version for that turn. Use the left/right arrows to switch the active branch; all generated versions are kept.
- **Delete**: deleting a message recursively removes its later active branch; deleting a conversation removes the conversation and all of its messages.

### Scrolling and interaction

- **Send pins to bottom**: after sending, the view locks and smoothly scrolls to the newest user bubble without waiting for the first streaming chunk.
- **Thinking panel**: expand or collapse the reasoning chain; it follows the stream automatically. Tool-call cards support live argument expansion, log viewing, and one-click download of generated files.
- **Follow-ups and queuing**: a follow-up typed just as a run completes (or at the end of the stream) is saved and drives the next round.

### Artifact list and preview

- After each assistant message, files generated in that turn are listed below the body, deduplicated by path with the latest kept; hiding the list never deletes the files.
- With **Hide artifact list** enabled on the Agent, the list is hidden, but artifacts can still be opened or downloaded from the tool card.
- Clicking an artifact, image, or source opens the preview panel, which supports images, video, audio, PDF, DOCX, PPTX, tables (CSV/XLSX, …), HTML, Markdown, Mermaid, and plain text. PDF is read-only; DOCX supports thumbnails, page numbers, and zoom; CSV is decoded as UTF-8 first, falling back to GB18030.
- Previews are **authenticated**: protected artifacts, generated images, and videos require the current conversation's credentials; without sign-in or permission the UI never falls back to the raw URL.
- When a preview cannot be shown, the UI distinguishes: file too large (default 20 MiB limit), not signed in, no permission, unsupported type, and parse failure.
- On desktop the preview opens in a right-hand panel, resizable by default (minimum 400px); on narrow viewports it becomes a full-screen overlay and the drag handle is hidden.

### Background runs and reconnection

Runs continue on the server; closing the page, refreshing, or switching conversations does not interrupt the model loop.

- When you reopen a conversation, the UI first checks whether it still has an unfinished reply, then either continues receiving the remaining output or loads the full history.
- A resumed reply does not re-render content already shown; a question waiting for your answer is restored along with the run.
- To really end a run, click **Stop**; a refresh only leaves the page temporarily.

### Message branches

A conversation can contain multiple branches:

```
Main conversation:
You: Tell me about AI
Agent: AI is...

Branch 1 (edited message):
You: Tell me about ML
Agent: ML is...

Branch 2 (regenerated):
Agent: AI, or artificial intelligence...
```

Use the arrow buttons to navigate branches.

## Managing Conversations

The conversation sidebar supports creating, selecting, renaming, and deleting **your own** conversations. The title is up to `200` characters and is the only editable conversation setting.

### New

Click **New chat (SquarePen)** at the top of the sidebar; the conversation is actually created when the first message is sent.

### Rename

Open a conversation's **...** menu in the sidebar and select **Rename**.

### Delete

Open the **...** menu and select **Delete**, then confirm. The conversation and its messages are removed and cannot be recovered.

### Search

<Callout type="warn">
  The Agent chat page (`/chat/{agent_id}`) has **no** conversation search box — the sidebar only offers new, select, rename, and delete. To find conversations by keyword, use the **Logs** page or the admin **Activity Log** page below.
</Callout>

Both searches match **keywords against the conversation title or conversation number**, never message bodies:

| Location | Path | Scope |
| --- | --- | --- |
| Agent **Logs** page | `/app/apps/{agent_id}/logs` | **Your own** conversations for that Agent; also filter by creation time and sort by updated time / creation time / message count. Requires permission to view conversations |
| Admin **Activity Log** page | `/activities` (**Conversations** tab) | **Every user's** conversations on the platform, filterable by team, Agent, and user. Requires admin permission to view conversations |

### Logs page

The Agent **Logs** page (Agent sidebar > **Logs**) lists conversations by time and search term; selecting one shows variables, model, token usage, response time, reasoning, and knowledge sources.

<Callout type="warn">
  The current implementation has no archiving, multi-user collaboration comments, or PDF export flow. Do not treat deletion as archiving; deletion cannot be undone.
</Callout>

## Best Practices

### Writing effective prompts

**✅ Do:**
```
Good: "What are the steps to reset my password in the
admin dashboard?"

Good: "Summarize the key points from the Q3 report
about revenue growth"

Good: "Compare the features of Plan A and Plan B in
a table format"
```

**❌ Don't:**
```
Bad: "password?"
Bad: "tell me everything"
Bad: "help"
```

**Tips:**
- Be specific about what you want
- Specify format if needed (table, list, summary)
- Provide relevant context
- Ask one thing at a time for complex topics

### Managing context

**Start a new conversation when:**
- Switching to an unrelated topic
- The Agent seems confused about context
- You want a fresh start

**Continue a conversation when:**
- Asking follow-up questions
- Building on previous answers
- Maintaining context is important

### Using knowledge bases effectively

**✅ Do:**
- Ask specific questions about documents
- Request sources: "According to the manual..."
- Mention document names if known
- Follow up for clarification

**❌ Don't:**
- Ask about information not in the knowledge base
- Expect the Agent to know real-time information
- Assume all documents are indexed

For detailed context management, see [Memory and Context](./memory).

## Troubleshooting

### Agent not responding

**Problem**: No response after sending a message

**Solutions:**
1. Check your internet connection
2. Refresh the page
3. Check if the Agent is published
4. Try a different Agent
5. Contact the administrator

### Slow responses

**Problem**: The Agent takes a long time to respond

**Solutions:**
1. Check your internet speed
2. Simplify your question
3. Try during off-peak hours
4. Contact the administrator about server load

### Irrelevant responses

**Problem**: The Agent gives unrelated answers

**Solutions:**
1. Rephrase your question more clearly
2. Provide more context
3. Start a new conversation (clear context)
4. Check whether the Agent has a relevant knowledge base
5. Try a different Agent specialized for your topic

### Sources not showing

**Problem**: No source citations in knowledge base answers

**Solutions:**
1. Verify the Agent has a knowledge base connected
2. Check that the Agent's RAG mode is not "off" and the **Citations** switch is on
3. Ask more specific questions
4. Verify documents finished processing (status: completed)

### No question form appears

**Problem**: The Agent says it needs more information, but no question form appears

**Solutions:**
1. Confirm **Interactive questions** is enabled in the Agent **orchestration** area and that the Agent was republished
2. Check whether the answers were already submitted or skipped — each interaction is consumed once
3. Refresh the page; a run still waiting for an answer restores the form

### Reply looks cut off after refresh

**Problem**: After a refresh or conversation switch, the reply appears interrupted

**Solutions:**
1. Wait a moment: the run keeps executing in the background and the page continues receiving the remaining output
2. If the run already finished, history is reloaded in full and nothing is lost
3. To really abort, click **Stop** instead of relying on a refresh

### File upload fails

**Problem**: Cannot upload files

**Solutions:**
1. Check file size (must be under 10 MB)
2. Verify the file format is supported
3. Check if the Agent allows file uploads
4. Try a different file
5. Contact the administrator
