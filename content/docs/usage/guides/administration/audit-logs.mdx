审计日志记录系统内的资源操作：操作者、动作、资源、变更前后快照与来源 IP。敏感字段在记录和展示时自动脱敏，原始密钥不会出现在日志中。

查看审计日志需要审计日志查看权限，导出需要导出权限；权限由管理员在角色中分配，见[角色与权限](./roles-permissions.mdx)。

## 审计日志记录什么

每种事件都会记录操作者、时间、资源、操作类型、状态与变更详情。按大类分为：

### 认证事件

登录成功、登录失败、登出与注册。记录账号、时间、来源 IP、浏览器标识、认证方式、是否使用双因素，以及失败原因和尝试次数。

### 用户管理事件

管理员创建、更新、删除、启用或停用用户。更新类事件保存变更前后的字段快照。

### 团队管理事件

创建团队、修改团队信息、添加或移除团队成员、转让所有权。

### Agent 与工作流事件

创建、更新、发布、删除 Agent 与工作流。更新类事件保存变更前后的字段，例如提示词或迭代上限。

### 沙箱任务事件

代码沙箱任务的生命周期：开始、完成、失败、取消与恢复。只记录任务标识、来源与结果，**不记录**代码、参数、输出或原始错误文本；失败记录给出稳定的错误分类，而不是堆栈信息。

### API Key 事件

创建、激活与停用 API Key。记录名称、权限范围、绑定的 Agent/工作流数量与过期时间。

### 站点设置事件

单项更新、批量更新与重置站点设置。记录设置项与变更前后的值。

### 安全事件

修改密码、重置密码、启用或停用账号。记录操作者、目标用户与来源 IP。

## 查看与筛选

在**管理后台** > **审计日志**查看。每条记录包含：时间、用户、动作、资源类型、资源名称、操作（创建/读取/更新/删除）、状态、IP 地址与详情。

筛选条件：

| 筛选 | 说明 |
| --- | --- |
| 用户 | 按操作者筛选 |
| 团队 | 按团队筛选 |
| 动作 | 精确匹配一个或多个动作，不支持通配符 |
| 资源类型 | 用户、团队、Agent、工作流等 |
| 资源标识 | 按具体资源筛选 |
| 状态 | 成功、失败等 |
| 时间范围 | 起止日期 |
| 关键词 | 对资源名称、资源标识和 IP 地址做不区分大小写的包含搜索 |

<Callout type="info">
  没有单独的 IP 筛选，但关键词可以匹配 IP 片段（如 `192.168.1.`）。关键词不解释 `*` 等通配符。
</Callout>

<Callout type="warn">
  **Roadmap：** 不能按变更字段或变更前后的值筛选，字段级快照只在详情和导出中可见；也不能保存筛选条件。
</Callout>

### 查看日志详情

点击日志条目查看完整详情：

- **基本信息**：记录编号、时间、操作者、动作、状态
- **资源信息**：资源类型、资源标识、资源名称、操作类型
- **请求信息**：来源 IP、浏览器标识、认证方式
- **变更详情**：变更前后的字段级快照（敏感值已脱敏）
- **元数据**：团队、模型、执行耗时等

<Callout type="warn">
  **Roadmap：** 没有「关联日志」视图。查找相关条目时，按相同用户、资源标识或时间范围筛选。
</Callout>

## 敏感数据脱敏

变更快照在保存前就会清洗，因此原始密钥不会出现在审计日志的任何位置：

- 密码、密钥、访问令牌、刷新令牌、私钥等字段整体遮蔽，只保留可识别的前几位。
- 邮箱只显示首尾字符，例如 `a***e@example.com`。
- 嵌套结构中的敏感字段同样遮蔽。
- 超长文本截断为预览：单个值超过 `500` 字符、或整段快照序列化后超过 `500` 字符时，只保存前 `500` 字符并追加省略标记。详情页与导出中看到的是**预览**，不是完整原文。

## 导出审计日志

支持 CSV 与 JSON 两种格式。导出使用与列表相同的筛选条件（资源标识除外），最多 `10,000` 条，按时间倒序。CSV 包含编号、时间、用户、动作、资源类型、资源名称、操作、状态、IP 与错误信息；JSON 保留完整条目与变更快照。

<Callout type="warn" title="导出的关键词范围略窄">
  列表页的关键词会匹配资源名称、资源标识与 IP 地址；**导出的关键词只匹配资源名称与 IP 地址**，并且不能按资源标识导出。用资源标识搜索后再导出，结果会比列表页多——排查问题时请以资源名称或 IP 作为导出条件。
</Callout>

导出是手动操作，没有定时导出或邮件投递。无导出权限的用户看不到导出按钮。

## 保留与归档

### 保留策略

审计日志默认保留 `365` 天，可设置为 `30-3650` 天。

**配置方式：** 前往**管理后台** > **站点设置** > **存储**，修改**审计日志保留天数**和**归档文件存储路径**。

### 手动归档

1. 前往**管理后台** > **站点设置** > **存储**。
2. 在**审计日志**分区点击**归档**并确认。
3. 归档在后台执行，页面显示进度；超过 `5` 分钟未完成会提示超时，可稍后刷新查看结果。

> **注意：** 手动归档入口在**存储**设置页，不在审计日志页——审计日志页只提供查看、筛选和导出。

归档按保留期限挑选日志，按月写入归档路径下的 JSON 文件；同一月份的文件会追加。归档完成后，已归档日志**从数据库删除**。

<Callout type="warn">
  归档会删除数据库中的原始记录，只留下归档文件。归档路径必须位于持久存储上，否则容器重建会丢失唯一副本；触发前确认保留天数符合合规要求。
</Callout>

<Callout type="warn">
  **Roadmap：** 没有定时自动归档，必须手动触发；归档目标只能是本地路径，不能直接写入对象存储；也没有归档恢复流程。
</Callout>

## 统计与限制

审计日志页顶部有四张统计卡：日志总量（全部时间）、今日数量、失败数量，以及近 7 天的活跃用户数，用于快速判断系统活动。

**未实现（Roadmap）：** 审计报告生成器、实时监控仪表盘、失败登录或批量删除的自动告警。需要安全告警时使用[自动通知](./notifications.mdx)中的安全事件与外部渠道。

## 最佳实践

- 定期审查登录失败、权限相关和批量删除类事件。
- 关键操作后按资源标识筛选，确认变更内容符合预期。
- 为审计日志查看与导出权限设置专人，不要下发到日常业务账号。
- 归档前确认归档路径位于持久存储并有备份，归档后保留归档文件的访问记录。
- 用审计日志满足合规要求时，先确认保留天数覆盖监管期限。
