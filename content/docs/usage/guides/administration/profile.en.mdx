Personal settings are a **dialog**, not a standalone page: open them from the avatar menu by selecting **Profile**; the dialog is titled **Settings** and has five tabs: **Profile**, **Account**, **Tool Connections**, **WeChat iLink**, and **Feishu**. The WeChat and Feishu tabs hold personal channel settings (WeChat knowledge collection authorization, Feishu notifications, and personal Agent conversation settings) — see [Messaging integrations](../integrations/index.mdx). Time zones, active session lists, data export, and privacy switches are not implemented (**Roadmap**).

This page covers interface actions and visible results. For the fields and error codes of the profile, password, and account endpoints see the [Users API](../../../api/users.mdx).

## Profile Tab

Maintains your avatar, username, and email.

| Field | Description |
| --- | --- |
| **Avatar** | Click to upload; `200x200` pixels recommended; JPG / PNG / GIF |
| **Username** | Globally unique, up to `50` characters; a duplicate reports that the username is taken |
| **Email** | Globally unique; a duplicate reports that the email is taken |

**Changing your email**: new-address verification is required only when the site has email verification on and the email actually changes.

1. After editing the email field, a verification area appears below it.
2. Click **Send code**; the new address receives a 6-digit code.
3. Enter the 6-digit code and click **Save changes**.

- Resending has a `60`-second cooldown; the button shows the remaining seconds.
- A wrong or expired code rejects the save with an invalid-code message.
- On success the address is marked verified immediately and an audit log entry is written.
- Changing only the username or avatar needs no code; saving with no changes reports that there is nothing to save.

## Tool Connections Tab

Use this tab to manage external accounts that Agents and tool executions use in the **current team**. A connection separates credentials from the tool definition so passwords never end up inside an Agent.

- The list shows the tool name, account label, level (personal/team), status (available / re-authorization required), and default badge.
- **Add connection**: pick a tool that declares connection fields, then fill in API keys, headers, or database fields, or choose **Connect** to complete OAuth.
- **Set default**: when a tool has several connections, mark one as default. With no default and exactly one personal connection, it is used automatically.
- **Reconnect / disconnect / delete**: reconnect when OAuth expires; disconnect only revokes authorization, while delete removes credentials permanently.
- Team connections are managed by team owners or administrators; only the owner can change a personal connection.

For selection rules and security boundaries, see [Tool Connections](../tools/tool-connections.mdx).

## Account Tab

From top to bottom the tab shows **Connected Accounts** (only when an SSO connection exists) → **Two-Factor Authentication** → password → **Danger Zone**.

### Connected Accounts (SSO)

The card lists connected SSO providers with the provider icon, display name, and **last sign-in** time.

- Click **Disconnect** and confirm in the dialog to unlink that provider.
- **Anti-lockout guard**: if the account has no local password and this is its only SSO connection, the system refuses with a message that the only sign-in method cannot be disconnected.
- **Link Feishu**: the card lists available Feishu logins (they appear once an administrator enables Feishu user login). Click **Link Feishu** to open Feishu authorization; after confirming, the Feishu identity is bound to the current account and can be used to sign in.
- Other providers show no link button: their connections are established automatically by email during sign-in; see [SSO Configuration](./sso.mdx).

### Two-Factor Authentication (TOTP)

**While disabled**: the card shows **Two-factor authentication disabled**. Click **Enable two-factor authentication** to open the wizard:

1. The first step explains what 2FA does.
2. The second step shows a QR code (issuer `Clouisle`); scan it with an authenticator app or **enter the secret manually**.
3. The third step verifies the current 6-digit code.
4. The fourth step saves one-time backup codes — **10** are generated, formatted `XXXX-XXXX`, downloadable or copyable.
5. The last step confirms completion.

<Callout type="info">
  Generating the secret does **not** enable 2FA yet; only a successful code check enables it.
</Callout>

**While enabled**: the card shows **Two-factor authentication enabled**, the **enabled on** time, and the number of remaining backup codes, with two actions:

- **Regenerate backup codes**: enter the current 6-digit code to generate a new set of 10, and **all old codes stop working immediately**; the new codes can be downloaded or copied in the dialog.
- **Disable two-factor authentication**: the confirmation dialog requires **both** the account password and the current code (or switch to backup-code input). On success the secret and backup codes are cleared and the state returns to disabled.

Failed codes, rate limiting, and lost-access handling are covered in [Sign-In and Account Security](./authentication.mdx).

### Password

The card title depends on the account type:

- **Change password** (the account has a local password): enter the **current password**, **new password**, and **confirm new password**, then click **Update password**.
- **Set password** (the account was created through SSO and has no local password yet): enter only the new password and confirmation.

The **password status** block loads only for local accounts:

- Expired shows a red alert; fewer than 7 days remaining shows a yellow warning; the **password expiration time** is shown as well.
- Users exempted from the expiration policy do not see this block.

Common responses:

| Case | Result |
| --- | --- |
| Current password is wrong | Reports that the current password is incorrect |
| Policy violation or reused password | Lists the reasons |
| Minimum password age not met | Reports how many days remain |

On success the password timestamp refreshes, expiration is recomputed, the forced-change flag clears, and a password-changed notification is sent.

<Callout type="warn" title="Known limitation: 'Set password' for SSO accounts does not take effect">
  **Set password** does not actually save today: the interface reports success, but the password is not written (**Roadmap**). To give an SSO account its first local password, have an administrator set it directly in [User Management](./user-management.mdx).
</Callout>

### Deleting Your Account

<Callout type="error" title="Permanent deletion">
  Account deletion cannot be undone, and there is no temporary deactivation or reactivation flow. Back up or transfer important data before deleting.
</Callout>

The entry appears only when the site enables self-service account deletion (when off, the page reports that account deletion is disabled).

1. In the **Danger Zone** card, click **Delete Account**.
2. Read the warning in the confirmation dialog.
3. Enter your **current password**.
4. Click **Delete Account**.

Limits and impact:

- **Super Admins cannot delete themselves.**
- The check uses the local password, so **SSO accounts with no local password cannot self-delete**. An administrator must handle them (administrators likewise cannot delete a Super Admin).
- Cascading deletion: sessions and messages, Agent run records, personal memories, API keys, password history, SSO connections, team memberships (including Owner), user notifications, and role assignments.
- **Not deleted**: uploaded files, plus Agents / workflows / knowledge bases / tools / Skills — their creator is cleared and the resource stays in the team; the team itself also stays but loses its owner. **The system does not stop an owner from deleting their account and does not transfer ownership automatically**, so transfer ownership first.

After deletion the local sign-in state is cleared and you are redirected to the sign-in page.

## Appearance and Language

Appearance and language are not in the personal settings dialog but in the **Theme Settings** panel in the navigation bar; changes apply immediately:

| Section | Options |
| --- | --- |
| **Theme** | Follow system / Light / Dark |
| **Sidebar** | Default / Inset / Floating |
| **Layout** | Default / Compact / Full width |
| **Header layout** | Default / Centered / Minimal |
| **Direction** | Left-to-right / Right-to-left |
| **Language** | English / 中文 |

- Theme, sidebar, layout, header layout, and direction are saved in the current browser and affect only this device.
- **Language** is written to a browser preference valid for one year; when signed in it also syncs to the account, so it persists across browsers.
- The **Reset** button at the bottom of the panel restores the default appearance (without changing language or account information).
- The sign-in and registration pages also have a language switcher in the corner, usable without signing in.

## API Keys

API keys are managed on a separate page, not in personal settings:

1. Open the avatar menu and select **API Keys** (shown only when the account has API key viewing permission).
2. Or navigate directly to `/app/api-keys`.

Creation, binding, deactivation, and limits are covered in [API Keys](./api-keys.mdx).

## My Memories

**My Memories** (`/app/memories`) in the avatar menu opens your personal memory graph page, titled **My Memories** with the subtitle "Explore what the AI has learned about you". There you can:

- Search memory entities by keyword, or filter by entity type.
- Switch the graph between **Grid / Hierarchical / Radial** layouts, with zoom in, zoom out, and fit-to-view.
- Inspect an entity's attributes, outgoing and incoming relations, access count, and last access time.
- Use **Select Mode** to pick several entities and **Delete selected**, or edit a single entity's description and delete one entity/relation.
- With no memories yet, a **No memories yet** empty state offers **Start conversation** to create some.

For extraction rules, entity and relation types, retrieval, and time decay, see [Memory and Context](../agent/memory.mdx).

## Notification Center

The notification center (`/app/notifications`) collects site-wide, team, and personal notifications, with search, unread filtering, and mark-as-read; the bell in the avatar menu shows the unread count (`99+` above 99).

Automatic notifications cover document processing, workflow runs, Agent publishing, API keys expiring/expired (7 / 3 / 1 days remaining), password expiration, account lockout, and new-device sign-in security events.

<Callout type="warn">
  This version has **no user-facing per-type switches, email digests, quiet hours, or push preferences** — delivery channels and global switches are managed by an administrator in site settings. Browser desktop notification permission is granted locally by the user.
</Callout>

See [Notifications and External Channels](./notifications.mdx) for details.

## Troubleshooting

### Cannot Save the Profile

1. Check the network connection and confirm required fields are filled in.
2. Read the error under the field (e.g. username taken, email taken).
3. When changing the email, confirm you sent and entered the 6-digit code.
4. Refresh the page and retry.

### No Email Verification Code

1. After clicking **Send code**, check the inbox and spam folder.
2. Note the 60-second resend cooldown and retry afterwards.
3. Confirm you entered the **new** address — the code goes only there.
4. If the site has no mail service configured, sending fails outright; an administrator must configure mail first.

### TOTP Cannot Be Enabled or Access Is Lost

1. Confirm the device time syncs automatically (±30-second window).
2. Try signing in with a one-time **backup code**.
3. When backup codes run out, contact an administrator to unbind TOTP and re-bind.
4. Disabling TOTP requires both the password and a code.

### Cannot Delete the Account

1. If the button is missing, the site has disabled self-service account deletion.
2. Super Admin accounts cannot delete themselves.
3. SSO accounts auto-created without a local password cannot self-delete; contact an administrator.

### Interface Did Not Change After Switching Language

1. Wait for the page refresh (switching triggers one).
2. Clear site cookies and sign in again so the language preference syncs.
3. Confirm a browser translation extension is not overriding the interface text.

## Best Practices

**Recommended**

- Use a strong, unique password and enable TOTP; store backup codes offline.
- Keep your email address current — it is the only channel for password recovery and notifications.
- Periodically review connected SSO accounts and recent sign-in notifications.
- Transfer team ownership and export anything you need before deleting your account.

**Avoid**

- Disabling TOTP on a shared device.
- Ignoring security notifications.
- Relying on "Set password" in personal settings to establish the first password for an SSO account (see the known limitation above).
