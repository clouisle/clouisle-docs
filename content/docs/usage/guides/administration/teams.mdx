团队是 Clouisle 的资源隔离边界。团队成员角色为所有者、管理员、成员和观察者，团队内所有操作受权限代码控制。

## 创建团队

<Callout type="info">
  创建团队需要 `admin:team:create` 权限。
</Callout>

1. 前往**团队** > **创建团队**。
2. 填写团队信息：
   - **名称**：团队名称（必填）
   - **描述**：团队描述（可选）
   - **头像 URL**：团队头像地址（可选）
3. 点击**创建团队**。
4. 创建成功后，你自动成为该团队的所有者。

<Callout type="warn">
  **未实现 / Roadmap**：创建时指定所有者、添加初始成员、邀请/加入设置、资源限制均不属于团队创建流程。团队成员需创建后通过**添加成员**加入，所有权通过**转让所有权**转移。
</Callout>

创建后从工作台团队切换器选择它。新建 Agent、工作流和知识库时确认当前团队。

## 团队协作

团队协作通过共享资源实现：**Agent**、**工作流**和**知识库**在团队内共享，所有成员（受角色权限约束）均可访问。

> **未实现 / Roadmap**：共享对话、@提及、团队活动流、文档评论和团队内消息均未实现。协作通过共享资源与团队通知进行。

### 使用团队 Agent

1. 前往 **Agent** 部分。
2. 按当前团队筛选。
3. 选择团队 Agent。
4. 开始对话。
5. Agent 只能使用其配置中附加的知识库。

### 运行团队工作流

1. 前往 **工作流** 部分。
2. 选择团队工作流。
3. 点击 **"运行"**。
4. 提供输入。
5. 监控执行。
6. 查看结果。

工作流执行历史对所有团队成员可见（受角色权限约束），可查看谁在何时运行了工作流，并访问执行结果和节点详情。

### 访问团队知识库

1. 前往 **知识库** 部分。
2. 选择团队知识库。
3. 浏览或搜索文档。
4. 查看和下载文档（受权限约束）。

权限约束：
- 查看/搜索：成员及以上（观察者也可）
- 上传：成员及以上
- 删除：成员及以上（基于角色）

## 团队通知

团队相关自动通知会发送到应用内通知中心：

| 类型 | 触发时机 |
|------|----------|
| `team.member_added` | 成员被添加时（通知新成员和团队） |
| `team.member_removed` | 成员被移除时 |
| `team.role_changed` | 成员角色变更时 |
| `team.ownership_transferred` | 所有权转让时 |
| `team.model_granted` / `team.model_revoked` | 团队模型访问权限变更时 |

这些是全局自动通知；发送渠道由管理员配置（参见[通知与外部渠道](./notifications.mdx)）。

> **注意**：没有按团队的通知配置，也没有基于提及的通知。

## 查看团队详情

### 团队概览

在团队列表中点击团队进入详情页，查看完整信息：

- 成员数量与角色分布（所有者、管理员、成员、观察者）
- 创建时间与更新时间
- 所有者信息

<Callout type="warn">
  **未实现 / Roadmap**：资源配额（Agent/工作流/存储限制）、使用活动（对话、执行、API 调用）、团队设置（成员邀请、加入请求、API 密钥）未显示或不可配置。团队无数量限制或邀请设置。
</Callout>

### 团队成员

在团队详情的**成员**标签中查看所有成员，包括用户名、邮箱、角色和加入时间。

### 模型授权

在团队详情的**模型授权**标签中，选择全局模型并设置 Token/请求配额、启用状态和优先级。参见[管理团队模型](../models/manage-models.mdx)。

团队详情界面没有独立的资源标签。

## 加入团队

<Callout type="info">
  没有邮件邀请流，没有"接受/拒绝邀请"操作，也没有加入请求/审批流。成员通过用户 ID 直接添加。
</Callout>

### 成为成员的方式

1. **被所有者/管理员添加**：团队所有者或管理员通过用户 ID 添加你，并分配角色（管理员、成员或观察者）
2. **默认团队**：如果管理员配置了默认团队，新注册用户会自动以配置的角色加入（默认 `member`）
3. **创建为所有者**：创建团队的用户成为其所有者

### 成员通知

当你被添加到团队时，会收到团队通知（`team.member_added`），团队也会收到通知。没有接受/拒绝操作——成员身份立即生效。

## 添加成员

1. 打开团队详情。
2. 点击**添加成员**。
3. 搜索用户（按用户名或邮箱）。
4. 选择角色：管理员、成员或观察者。
5. 点击**添加**。

成员角色含义：

| 角色 | 主要职责 |
| --- | --- |
| 所有者 | 完整团队控制、所有权转让 |
| 管理员 | 管理成员、模型授权和团队资源 |
| 成员 | 按权限创建和使用资源 |
| 观察者 | 只读查看可访问资源 |

## 团队角色与权限

团队角色控制成员在团队内的操作权限。它们与全局系统角色分离。全局角色提供系统级能力；团队角色被镜像为团队作用域的角色分配，仅在该团队内生效。团队角色**不授予**管理仪表盘（`admin:*`）权限。

### 角色层级

```
所有者（最高权限）
  ↓
管理员
  ↓
成员
  ↓
观察者（最低权限）
```

### 审计与分析

审计日志、管理仪表盘和数据导出是**全局管理员能力**，不是团队角色。它们由具有相应 `admin:*` / `audit:*` 权限的全局角色授予——仅靠团队角色永远不会授予这些权限。

| 权限 | 所有者 | 管理员 | 成员 | 观察者 |
|------|--------|--------|------|--------|
| 查看审计日志（管理仪表盘） | 全局角色 | 全局角色 | ❌ | ❌ |
| 查看管理仪表盘 | 全局角色 | 全局角色 | ❌ | ❌ |

### 作用域边界

团队角色仅在其被分配的团队内适用。团队管理员可以管理该团队内的资源，但不会获得管理仪表盘权限，除非全局角色单独授予 `admin:*` 权限。

### 所有者角色

**所有者拥有对团队的完全控制：**

- 完全管理访问权限
- 可以删除团队
- 可以转让所有权
- 对所有决策拥有最终决定权

**独占权限：**
- 删除团队
- 转让所有权给其他成员
- 改变成员角色

**与管理员共享：**
- 添加/移除成员
- 从**管理团队**更新团队信息

> **注意**：计费和订阅**未实现**。

**限制：**
- 每个团队只有一个所有者
- 不转让所有权无法离开团队
- 不能被他人移除
- 不能降级自己的角色（必须先转让）

### 管理员角色

**管理员帮助管理团队：**

- 管理团队成员
- 从**管理团队**配置团队信息
- 监督资源
- 监控团队活动
- 支持团队成员

**成员管理：**
- 添加新成员（通过用户 ID）
- 移除成员（所有者除外）
- 改变成员角色（所有者除外）

**资源管理：**
- 创建/更新/删除团队资源（受团队作用域 RBAC 允许）
- 管理 Agent、工作流、知识库
- 配置资源设置

**团队信息：**
- 从**管理团队**更新团队名称、描述和头像

**监控：**
- 查看团队资源和使用情况
- 审计日志 / 管理仪表盘需要具有相应 `admin:*` / `audit:*` 权限的全局角色——仅靠团队管理员角色不授予这些权限

**限制：**
- 不能删除团队
- 不能转让所有权
- 不能移除或降级所有者
- 不能将自己的角色变更为所有者

### 成员角色

**成员是常规团队用户：**

- 创建和使用资源
- 与团队协作
- 管理自己的资源
- 遵循团队准则

**资源创建：**
- 创建 Agent
- 创建工作流
- 创建知识库
- 上传文档
- 创建 API Key

**应用协作：**
- 保存团队 Agent
- 保存团队工作流
- 使用团队 Agent 和工作流

**资源使用：**
- 与所有团队 Agent 对话
- 运行所有团队工作流
- 搜索所有团队知识库
- 使用团队工具

**自己的资源管理：**
- 管理自己的 API Key
- 更新知识库文档

**工具与 Skill：**
- 成员可以创建、编辑（自己的工具）和删除工具与 Skill（他们持有 `tool:create/update/delete` 和 `skill:create/update/delete`）
- 编辑他人的工具需要团队所有者/管理员

**知识库：**
- 成员可以创建知识库、上传/重命名/删除文档以及搜索（他们持有 `kb:create/update/delete`）
- 文档删除不受文档所有权限制——`kb:delete` 权限在团队范围内适用

**限制：**
- 不能从**管理团队**管理团队信息
- 不能添加或移除成员
- 不能改变成员角色
- 不能删除或发布 Agent 和工作流
- 不能更新他人的工具
- 不能查看审计日志
- 不能访问管理仪表盘

### 观察者角色

**观察者拥有仅查看/使用的访问权限：**

- 查看团队资源
- 使用 Agent 和工作流
- 搜索知识库
- 监控团队活动

**读取访问：**
- 查看所有团队 Agent
- 查看所有团队工作流
- 查看所有团队知识库
- 查看团队成员

**有限使用：**
- 与 Agent 对话
- 运行工作流
- 搜索文档
- 下载文档（如果允许）

**限制：**
- 不能创建任何资源
- 不能更新任何资源
- 不能删除任何资源
- 不能从**管理团队**管理团队信息
- 不能添加成员
- 不能上传文档
- 不能创建 API Key

**适用场景：**
- 外部顾问
- 临时访问
- 只读审计员
- 利益相关者

### 默认团队角色

配置默认团队时，新用户可以自动添加为 `viewer`、`member` 或 `admin`。如果未配置角色，则默认为 `member`。`owner` 永远不会自动分配。

### 自定义角色

> **注意：** 自定义角色**未实现**。团队使用四个固定角色（所有者、管理员、成员、观察者），每个角色映射到一组固定权限。

## 改变成员角色

1. 在成员列表中找到目标成员。
2. 点击**改变角色**。
3. 选择新角色。
4. 确认变更。

改变角色会产生通知和审计记录。

## 移除成员

1. 在成员列表中找到目标成员。
2. 点击**移除**。
3. 确认移除。

移除后：

- 成员立即失去团队资源访问权限
- 个人资源保留
- 后续可重新添加

所有者不能被移除。

## 切换团队

1. 点击导航栏中的**团队切换器**。
2. 选择不同的团队。
3. 界面更新显示该团队的资源。

## 离开团队

1. 打开团队（团队切换器或团队视图）。
2. 选择 **"离开团队"**。
3. 确认离开。
4. 你被从团队中移除。

**注意**：团队所有者不能离开，直到所有权被转让（参见[转让所有权](#转让所有权)）。

离开后：
- 你失去对团队资源的访问权限
- 你的对话被保留

## 转让所有权

1. 打开团队详情。
2. 在成员列表中找到新所有者。
3. 点击**转让所有权**。
4. 确认转让。

转让后原所有者失去所有者权限，变为普通成员。确认目标成员后再执行。

## 编辑团队

1. 打开团队详情。
2. 点击**编辑**。
3. 更新字段：名称、描述、头像 URL。
4. 点击**保存更改**。

## 删除团队

1. 打开团队详情。
2. 点击**删除团队**。
3. 查看删除影响：
   - **将被删除**：所有团队资源（Agent、工作流、知识库）、所有团队数据
   - **将被保留**：成员账户、审计日志（用于合规）
4. 输入团队名称确认。
5. 点击**永久删除**。

<Callout type="error">
  此操作不可逆。默认团队不能删除。
</Callout>

## 最佳实践

### 有效协作

**✅ 推荐：**
- 为共享资源使用描述性名称
- 保持资源有序
- 记录资源用途
- 通过通知让团队了解情况

**❌ 避免：**
- 创建重复资源
- 未经讨论删除共享资源

### 角色分配

**✅ 推荐：**
- 遵循最小权限原则
- 根据职责分配角色
- 定期审查角色
- 记录角色分配
- 沟通角色变更
- 培训成员了解其权限

**❌ 避免：**
- 给所有人管理员访问权限
- 不必要地分配所有者角色
- 不通知就改变角色
- 忘记审查权限
- 忽视基于角色的安全

### 安全管理

**✅ 推荐：**
- 限制所有者和管理员角色
- 对仅查看/使用访问使用观察者角色
- 定期审查审计日志
- 监控角色变更
- 角色变更需要审批
- 记录角色变更原因

**❌ 避免：**
- 共享所有者凭据
- 允许未经授权的角色变更
- 忽视可疑活动
- 跳过角色审查
- 忘记审计权限

## 故障排除

### 无法访问团队资源

**问题：** 资源不可见或无法访问

**解决方案：**
1. 检查你是否在正确的团队中
2. 验证资源是否已发布
3. 检查你的角色权限
4. 刷新页面
5. 联系团队管理员

### 未收到团队通知

**问题：** 没有团队通知

**解决方案：**
1. 验证你是团队成员
2. 在 `/app/notifications` 检查通知中心
3. 询问管理员是否启用了自动通知类型
4. 刷新页面

### 无法执行操作

**问题：** 操作被禁用或失败

**解决方案：**
1. 检查你当前的角色
2. 验证所需权限
3. 联系团队管理员/所有者
4. 如果需要，请求角色变更
5. 检查资源是否被锁定

### 角色变更未生效

**问题：** 角色已改变但权限未变

**解决方案：**
1. 退出并重新登录
2. 刷新页面
3. 清除浏览器缓存
4. 检查变更是否已保存
5. 联系管理员

### 无法改变角色

**问题：** 改变角色选项被禁用

**解决方案：**
1. 验证你是所有者或管理员
2. 检查目标是否是所有者（不能改变）
3. 验证成员是否仍在团队中
4. 刷新页面
5. 联系管理员

### 失去管理员访问权限

**问题：** 意外失去管理员权限

**解决方案：**
1. 联系团队所有者
2. 请求恢复角色
3. 解释发生了什么
4. 所有者可以恢复你的角色
5. 如果所有者不可用，联系管理员

## API 端点

团队管理通过以下端点实现，需要 JWT 用户会话认证（不接受 API Key）：

| 方法 | 路径 | 用途 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/v1/teams/my` | 列出当前用户所属团队 | `team:read` |
| GET | `/api/v1/teams/{team_id}` | 获取团队详情（含成员列表） | `team:read` |
| POST | `/api/v1/admin/teams` | 创建团队 | `admin:team:create` |
| PUT | `/api/v1/teams/{team_id}` | 更新团队信息 | `team:update` |
| DELETE | `/api/v1/admin/teams/{team_id}` | 删除团队 | `admin:team:delete` |
| POST | `/api/v1/teams/{team_id}/members` | 添加团队成员 | `team:manage` |
| PUT | `/api/v1/teams/{team_id}/members/{user_id}` | 更新成员角色 | `team:manage` |
| DELETE | `/api/v1/teams/{team_id}/members/{user_id}` | 移除团队成员 | `team:manage` |

基础 URL：
- 平台接口：`/api/v1/teams`
- 管理接口：`/api/v1/admin/teams`

<Callout type="info">
  没有 `GET /api/v1/teams` 列出所有团队的端点。管理员可通过 `GET /api/v1/admin/teams`（分页，支持按名称或描述 `search`，默认 `page_size` 50）列出所有团队，需要 `admin:team:read` 权限。
</Callout>

完整的请求/响应格式、代码示例和错误码参见 [Teams API](../../../api/teams.mdx)。
