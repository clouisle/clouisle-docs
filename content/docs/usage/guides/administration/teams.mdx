团队是 Clouisle 的资源隔离边界：Agent、工作流、知识库、工具、Skill 都归属某个团队。团队内的一切操作都要同时通过「全局角色权限」和「团队成员角色」两层检查。

本页覆盖团队的创建、成员增删改、离开、所有权转让、删除，以及每步失败时看到什么。角色权限的完整模型见[角色与权限](./roles-permissions.mdx)与[权限与角色参考](../../../reference/permissions.mdx)。

## 创建团队

<Callout type="info">
  创建团队需要管理台的团队管理权限，入口在 **Admin** → **Teams**。普通成员看不到该入口。
</Callout>

1. 进入 **Admin** → **Teams**。
2. 点击 **Create Team**，填写：
   - **Team Name**（必填，全局唯一，重名时提示团队名已存在）
   - **Description**（可选）
   - **Team Avatar**（可选，从本地上传图片，支持 JPEG/PNG/GIF/WebP/SVG/ICO，建议 200×200、上限 10 MB）
3. 保存。

创建者自动成为该团队的 **owner**。

<Callout type="warn">
  **未实现 / Roadmap**：创建时指定其他所有者、添加初始成员、邀请/加入设置、资源配额均不在创建流程内。成员需创建后通过**添加成员**加入；所有权通过**转让所有权**转移。
</Callout>

创建后在团队切换器里选择它。新建 Agent、工作流、知识库时确认当前团队，否则资源会落到错误的团队里，后续只能靠重建来纠正。

## 两个团队界面

团队切换器提供两个入口，权限与能力完全不同：

| 入口 | 位置 | 需要 | 用途 |
| --- | --- | --- | --- |
| **管理全部团队（系统后台）** | **Admin** → **Teams**（`/teams`） | 管理台的团队查看权限 | 列出系统内所有团队（分页、可按名称/描述搜索）、创建、改信息、删除、批量删除 |
| **管理当前团队** | `/app/team` | 页面本身只要求是该团队成员；入口链接仅对超级管理员或团队 owner/admin 出现 | 成员管理、团队基本信息编辑、离开、转让所有权、查看已授权模型（只读） |

`/app/team` 页面的**模型授权页签是只读的**：展示当前团队已授权的模型、启用状态与今日用量/限额，并提示由系统管理员分配。模型授权的写操作全部要求超级管理员（见下）。

## 团队详情与成员

### 团队概览

`/app/team` 头部显示团队头像、名称、**默认团队**徽标以及**你在该团队内的角色**徽标。成员页签列出头像、用户名、邮箱与角色，并支持按用户名/邮箱本地过滤。

<Callout type="warn">
  **未实现 / Roadmap**：团队详情不显示资源配额（Agent/工作流/存储上限）、使用活动统计（对话数、执行数、API 调用），也没有团队级通知设置或独立资源页签。
</Callout>

### 模型授权

模型授权是**超级管理员专属**能力：团队成员只能查看，授权、批量授权、修改配额、撤销都由管理员在 **Admin** → **Teams** 的团队详情里完成，或在**管理当前团队**的**模型授权**页签查看结果（该页签只读）。

可配置项包括每日/每月 Token 上限、每日/每月请求上限、启用状态与优先级。授权或撤销会向团队发送站内通知。细节见[管理团队模型](../models/manage-models.mdx)。

## 添加成员

<Callout type="info">
  需要团队管理权限，且你在该团队内是 **Owner** 或 **Team Admin**。普通成员与只读成员看不到添加按钮，强行操作会被拒绝。
</Callout>

1. 打开 `/app/team` 的**成员**页签，点击 **Add Member**（仅在有管理能力时显示）。
2. 在「用户名或邮箱」输入**目标用户的完整用户名或邮箱**。
3. 选择角色：**Admin**、**Member**、**Viewer**（不提供 **Owner**）。
4. 确认。

匹配规则与校验：

| 情况 | 结果 |
| --- | --- |
| 用户名精确匹配，或邮箱不区分大小写精确匹配 | 命中用户 |
| 都匹配不到 | 提示用户不存在——**没有模糊搜索/下拉选人** |
| 只输入片段（如 `john` 前缀） | 匹配不到，同样提示用户不存在 |
| 用户已经是成员 | 提示已是团队成员 |
| 尝试选 Owner | 不允许，添加成员时不能指定 Owner |
| 选 Admin，但目标用户没有全局的团队管理权限 | 操作被拒绝 |

<Callout type="error" title="给团队 Admin 之前先给全局角色">
  把一个没有全局团队管理权限的用户加为团队 **Admin** 会直接被拒。顺序必须是：先在 **Admin** → **Users** 给他 **Team Admin** 角色（或任何含团队管理能力的角色），再回团队里设为 **Admin**。
</Callout>

添加成功后：新成员收到团队通知，团队也收到一条汇总通知；成员身份**立即生效**，没有邀请/接受流程。

## 改变成员角色

<Callout type="info">
  只有团队 **Owner**（或超级管理员）能改角色。团队 **Admin** 无法修改成员角色。
</Callout>

1. 在成员列表找到目标成员，打开 **...** 菜单。
2. 选择 **Change Role**，在新角色下拉中选 **Admin** / **Member** / **Viewer**。
3. 保存。

校验规则：

| 情况 | 结果 |
| --- | --- |
| 调用者不是 Owner（也不是超级管理员） | 操作被拒绝 |
| 目标成员当前是 Owner | 不能修改 Owner 的角色，只能走转让所有权 |
| 新角色选 Owner | 不允许，提升所有者只能走转让所有权 |
| 新角色选 Admin，但目标用户没有全局团队管理权限 | 操作被拒绝 |
| 目标用户不是该团队成员 | 提示成员不存在 |

变更成功后目标用户收到通知。

<Callout type="warn">
  成员角色变更**不写审计日志**：团队审计只覆盖创建/更新/删除团队、添加/移除成员与团队模型授权动作。
</Callout>

**界面还会额外隐藏按钮**：你不能操作自己，团队 Admin 也看不到其他 Admin 与 Owner 的操作菜单。

## 移除成员

| 场景 | 说明 |
| --- | --- |
| 移除他人 | 需要团队管理权限且是 Owner/Admin；菜单同样受上面“不能操作他人 Admin/Owner”的限制 |
| 移除自己 | 任何成员都可以，等价于离开团队 |

共同限制：**Owner 永远不能被移除**（包括自己）；目标不是成员时会提示成员不存在。

移除后：该用户立即失去该团队全部资源访问权限；只删除团队成员关系，**不会删除他的对话、API 密钥或个人资源**（对话因失去团队访问权而不可再访问）。团队与被移除者都会收到通知。之后可以重新添加。

## 离开团队

1. `/app/team` → **Settings** 页签 → 危险区域，点击 **Leave Team**。
2. 在确认对话框中确认。

<Callout type="error">
  **Owner 不能离开团队**：危险区域会提示「作为团队所有者，你无法直接退出团队，请先转移所有权」。想走就必须先转让所有权。另外**默认团队**不显示离开按钮——这是界面行为，不是权限问题。默认团队需要管理员先在站点设置里改默认团队。
</Callout>

离开后你失去该团队资源访问权；已有对话保留。团队列表会刷新，页面跳回 `/app`。

## 转让所有权

<Callout type="info">
  需要团队管理权限且在该团队内是 **Owner**（或超级管理员）。团队 Admin 看不到该菜单项。
</Callout>

1. 打开 `/app/team` 成员列表，找到目标成员，**...** → **Transfer Ownership**（该菜单项只有 Owner 能看到）。
2. 确认对话框点击确认。

规则（按顺序执行）：

1. 目标必须是该团队成员，否则提示成员不存在。
2. 目标必须**已经持有全局团队管理权限**，否则操作被拒。同样地，先给全局角色，再转让。
3. 目标就是当前 Owner → 操作被拒。
4. 原 Owner 的成员角色被**降级为 Admin**，目标的成员角色改为 **Owner**。
5. 新旧 Owner 各收到一条通知。

<Callout type="warn">
  转让是不可逆的即时操作：原先的 Owner 只剩 Admin 权限，且**无法自行改回**（改角色要求 Owner）。确认目标人选后再执行。
</Callout>

## 编辑团队信息

需要团队管理权限且在该团队内是 Owner/Admin。

- `/app/team` → **Settings** 页签：可改团队名称、描述、头像（未通过校验时输入框禁用）。
- 管理台 **Admin** → **Teams** 的编辑对话框：同一批字段，需要管理台的团队修改权限。

字段与约束：名称必填且全局唯一（重名时提示团队名已存在）；描述可选；头像由上传组件写入。**没有**团队 slug、别名、域名等字段。

## 删除团队

<Callout type="error">
  删除团队是不可逆的破坏性操作，只能在管理台 **Admin** → **Teams** 执行。团队 Owner 在 `/app/team` 里**没有**删除入口。
</Callout>

1. 在团队列表点击目标团队的 **...** → **Delete Team**（默认团队不显示该项）。
2. 确认对话框点击确认——对话框只要求确认，**不需要输入团队名**。
3. 默认团队会被拒绝：默认团队不能删除。

删除影响：

| 会被删除 | 会被保留 |
| --- | --- |
| 团队记录与全部成员关系 | 成员的用户账户 |
| 该团队的 Agent、工作流、知识库、工具、Skill、资产 | 审计日志（合规用途） |
| 团队模型授权、工具配置、通知、导入会话 | 成员的账户数据（API 密钥归属用户个人，不随团队删除） |
| Agent 会话及其消息（随 Agent 级联） | — |

## 团队角色与权限

团队角色是四个固定值 **Owner** / **Admin** / **Member** / **Viewer**，**不单独携带权限清单**，只作为团队门限。实际能力是全局角色权限与团队门限的交集。

### 门限规则

- 团队管理类动作（改团队信息、管理成员、删除工具等）必须同时具备对应的全局权限**且**在该团队内是 Owner/Admin。
- 团队 **Viewer** 只能查看与执行（对话、运行工作流、检索知识库、执行工具与 Skill），其余写操作一律被拒绝。
- 超级管理员直接绕过成员关系与团队门限。

### 团队管理权限

| 操作 | Owner | Team Admin | Member | Viewer |
| --- | :-: | :-: | :-: | :-: |
| 查看团队与成员 | ✓ | ✓ | ✓ | ✓ |
| 改团队信息（名称/描述/头像） | ✓ | ✓ | ✗ | ✗ |
| 添加成员 | ✓ | ✓ | ✗ | ✗ |
| 改变成员角色 | ✓ | ✗ | ✗ | ✗ |
| 移除成员 | ✓ | ✓（不能动其他 Admin/Owner） | ✗ | ✗ |
| 离开团队 | ✗（须先转让） | ✓ | ✓ | ✓ |
| 转让所有权 | ✓ | ✗ | ✗ | ✗ |
| 删除团队 | ✗（需管理台） | ✗ | ✗ | ✗ |

### 团队内资源权限

| 操作 | Owner | Team Admin | Member | Viewer |
| --- | :-: | :-: | :-: | :-: |
| 创建 Agent / 工作流 / 知识库 | ✓ | ✓ | ✓ | ✗ |
| 编辑**他人**的 Agent / 工作流 / 知识库 | ✓ | ✓ | ✗ | ✗ |
| 删除 Agent、发布 Agent 与工作流 | ✓ | ✓ | ✗ | ✗ |
| 与 Agent 对话、运行工作流 | ✓ | ✓ | ✓ | ✓ |
| 创建/编辑自己的工具与 Skill | ✓ | ✓ | ✓ | ✗ |
| 编辑**他人**的工具 / Skill | ✓ | ✓ | ✗ | ✗ |
| 删除工具 | ✓ | ✓ | ✗ | ✗ |
| 知识库检索/测试、上传/重命名/删除文档 | ✓ | ✓ | ✓ | 只读检索 |
| 执行工具与 Skill | ✓ | ✓ | ✓ | ✓ |

<Callout type="warn" title="API 密钥不属于团队">
  API 密钥归属个人：普通用户只能看到自己的密钥，团队 Owner/Admin 也看不到、停用不了别人的密钥。团队成员角色对 API 密钥**没有任何影响**。
</Callout>

### 默认团队角色

站点设置中可以指定**默认团队**与**默认成员角色**，默认角色只接受 **Viewer / Member / Admin**（其他值回退为 Member，默认值也是 Member）。新用户注册与 SSO 自动创建时生效，已存在的成员关系不会被覆盖。**Owner 永远不会被自动分配**。

### 自定义团队角色

> **未实现。** 团队只有 Owner、Admin、Member、Viewer 四个固定角色，每个角色对应一组固定门限规则，不能为单个团队增删权限。需要精细权限时改用全局自定义角色（见[角色与权限](./roles-permissions.mdx)）。

## 团队协作与通知

团队协作通过共享资源实现：Agent、工作流、知识库、工具、Skill 在团队内共享，成员按角色门限访问。工作流执行历史对团队成员可见（受权限约束），可以看到谁在何时运行过。

团队相关自动通知（发送渠道由管理员在站点设置里配置，见[通知与外部渠道](./notifications.mdx)）：

| 事件 | 触发时机 | 接收方 |
| --- | --- | --- |
| 成员加入 | 添加成员 | 新成员 + 团队 |
| 成员移除 | 移除成员 | 被移除者 + 团队 |
| 角色变更 | 改变成员角色 | 被变更者 |
| 所有权转让 | 转让所有权 | 新旧 Owner 各一条 |
| 模型授权 / 撤销 | 授予或撤销模型 | 团队 |

> **未实现 / Roadmap**：没有按团队的通知配置，没有 @提及、共享对话、团队活动流、文档评论或团队内消息。

## 故障排除

### 无法访问团队资源

1. 确认左侧团队切换器选中了正确的团队。
2. 确认你是该团队成员（能打开 `/app/team` 说明是）。
3. 确认全局角色具备所需能力；团队 Viewer 只能读与执行。
4. 确认资源是否**私有**：私有资源对非创建者不可见，会被拒绝访问。

### 无法改变角色 / 菜单里没有「Change Role」

- 只有 **Owner**（或超级管理员）能改角色。
- 界面还会隐藏：你不能操作自己，团队 Admin 看不到其他 Admin 与 Owner 的操作菜单。
- 目标是 Owner 时不可改，要换人只能转让所有权。
- 想把某人升为团队 Admin，他必须已有全局团队管理权限。

### 加成员提示用户不存在

输入必须是**完整用户名**或**完整邮箱**（邮箱忽略大小写）。片段、昵称、显示名都匹配不到——系统不做模糊搜索。

### 加成员被拒绝

角色选了 Admin，但目标用户没有全局团队管理权限。先给他 Team Admin 全局角色，再设为团队 Admin。

### 转让所有权被拒

- 你不是 Owner（也不是超级管理员）。
- 目标不是团队成员，先加成员。
- 目标没有全局团队管理权限。
- 目标已经是 Owner。

### 无法离开团队 / 没有离开按钮

Owner 不能离开，默认团队也不显示该按钮。先转让所有权；默认团队需要管理员先在站点设置里改默认团队。

### 无法删除团队

- 入口只在管理台 **Admin** → **Teams**，需要管理台的团队删除权限。
- 默认团队不能删除。

### 角色变更后权限没变

浏览器缓存的前端权限快照可能过期：刷新页面或重新登录即可。后端每次请求实时判定，不需要等缓存过期。
