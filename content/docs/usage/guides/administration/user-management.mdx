用户管理在管理台 **Users**（`/users`）页面，按动作区分权限：查看列表、添加用户、修改/激活/停用/密码策略、删除用户。内置 **Admin** 角色具备这些全部能力。

本页只讲界面操作、可见结果与失败后的处理；账号的字段定义、接口与错误码见 [Users API](../../../api/users.mdx)。用户**角色**如何影响权限见[角色与权限](./roles-permissions.mdx)。

## 列表与筛选

用户列表分页加载，默认每页 `10` 条，可切换为 `20` / `50` / `100` 条，提供：

- **搜索框**：按用户名或邮箱模糊匹配（不区分大小写）。
- **状态筛选**：**活跃** / **已禁用** / **待审核**，可多选。
- **角色筛选**：按全局角色名过滤。
- 有改动时出现**重置**按钮，一次清空搜索与筛选。

页面顶部没有汇总卡片，但只要存在待审核用户，就会显示一条提示「有 N 个用户等待审核」，点击**查看待审核**可直接切到该筛选。

列表每行显示：用户名（超级管理员带徽标）、邮箱、SSO 图标、状态徽章、主角色、密码状态徽章、创建时间，以及行内操作菜单。

三种状态的含义：

| 状态 | 含义 |
| --- | --- |
| **活跃** | 账户可用，可以登录。 |
| **已禁用** | 账户被管理员关闭，无法登录，数据保留。 |
| **待审核** | 注册后等待管理员批准，批准前无法登录。 |

## 添加用户

1. 点击 **添加用户**。
2. 填写 **用户名**（全局唯一）、**邮箱**（全局唯一，需为合法邮箱）、**密码** 与 **确认密码**，并设置 **活跃** 开关。
3. 保存。

校验与默认行为：

| 情况 | 结果 |
| --- | --- |
| 用户名已存在 | 提示用户名已被占用 |
| 邮箱已存在 | 提示邮箱已被占用 |
| 未选择界面语言 | 使用站点设置中的默认语言（默认英文） |
| — | 新用户直接进入**活跃**状态，无需审批 |

<Callout type="warn">
  创建表单**不接受角色**：新用户没有任何全局角色，创建后必须通过**编辑**单独指派，否则只能看到公开资源、无法在团队内操作。
</Callout>

### 批量导入 / SSO 自动创建

> **未实现 / Roadmap。** 没有 CSV/JSON/Excel 用户导入，只能逐个添加，或在 SSO 首次登录时自动创建。

SSO 自动创建由管理员在**站点设置** → **安全**中控制：

| 设置 | 说明 |
| --- | --- |
| 自动创建用户 | 开启后 SSO 首次登录自动建号 |
| 默认全局角色 | 新用户的初始角色，首次初始化指向 **Viewer** |
| 默认团队与默认成员角色 | 新用户自动加入的团队与角色，只接受 Viewer/Member/Admin，缺省 Member；Owner 永不自动分配 |
| 按邮箱匹配已有账户 | 邮箱相同则关联到现有账户，而不是新建 |
| 新账户需要审批 | 开启后新账户为**待审核**状态，批准前无法登录 |

> **未实现 / Roadmap**：SSO 自动创建没有邮箱域白名单限制。

## 编辑用户

在列表行菜单点击**编辑**：

| 字段 | 说明 |
| --- | --- |
| **用户名** | 只读，创建后不可修改 |
| **邮箱** | 改为新邮箱 |
| **密码** | 可选。填写即改密（需通过密码强度校验，不满足时逐条提示原因）；留空保持不变 |
| **全局角色** | 多选，**整体替换** |
| **活跃** | 激活/停用开关 |

<Callout type="error">
  **用户名不可修改**：编辑表单中的用户名输入框是只读的。写错用户名只能删除重建。
</Callout>

### 角色改动的保护规则

角色是整体替换：保存时先清空再写入，未选中的角色会丢失；匹配不到的角色名被忽略。

若目标用户仍是某些团队的 **Owner/Admin**，而新角色集不再包含团队管理权限，保存会被拒绝。**先降级团队角色，再摘全局角色**，否则顺序反了会被挡住。

提交密码时系统会向该用户发送通知。

## 账户状态

在列表行菜单中执行：

| 操作 | 行为 |
| --- | --- |
| **激活** | 账户恢复可用；已是激活状态会提示已激活 |
| **禁用** | 账户立即无法登录；超级管理员不能被禁用；已禁用会提示已禁用 |

禁用的实际效果：

- 无法登录：密码登录与 API 密钥两条路径都会被拒绝，提示账户已禁用或待审核。
- 使用他名下 API 密钥的集成**立即失败**——密钥本身不会被改写，但认证时因用户已禁用而拒绝。
- 资源、团队归属、会话全部保留；重新激活即可恢复。

激活/禁用都会给用户发送站内通知，并写入审计日志。

## 删除用户

在列表行菜单点击**删除**，确认对话框会显示目标用户名并说明不可撤销。

唯一硬性拦截：**超级管理员账户不能删除**。

删除影响：

| 会被删除 | 会被置空/保留 |
| --- | --- |
| 账户本身、密码历史、通知与已读记录 | 他创建的 Agent / 知识库 / 文档 / 工具 / Skill（保留资源，创建者置空） |
| 个人对话及其消息、Agent 运行记录 | 他拥有的团队（保留团队，所有者置空） |
| 他名下的 API 密钥、个人记忆 | 审计日志（合规用途，不随账户删除） |
| 全部团队成员关系、作用域角色记录 | 团队内的共享资源与其他成员 |

<Callout type="error" title="删除团队 Owner 会让团队失去 Owner">
  删除某个团队的 Owner 会同时删掉他的成员关系，团队此后没有 Owner——只有超级管理员能改成员角色或补授所有权。要移除团队 Owner，请先在团队里转让所有权，再删除账户。
</Callout>

## 密码与密码过期

**没有**「重置为临时密码」或「从管理台发送重置邮件」的流程。管理员用下面这组行内操作配合全局密码策略：

| 操作 | 行为 |
| --- | --- |
| **强制修改密码** | 标记该用户下次登录必须改密，并发送高优先级通知 |
| **重置密码过期时间** | 从现在起重新计算密码过期时间，清空到期提醒 |
| **授予密码豁免** / **移除密码豁免** | 让该用户不受密码过期策略约束；授予豁免时同时取消强制改密 |
| 批量**强制修改密码** / 授予或移除豁免 | 对勾选的用户逐个执行并通知 |

这些操作只对**本地账户**出现（SSO 用户没有本地密码）。密码过期策略开启后，管理台 **Dashboard** 概览会出现**密码安全**卡片，显示已过期、即将过期与待强制改密的人数；未启用策略时这些数字为 0。

全局策略配置在**站点设置** → **安全**。

## TOTP（双因素）

- **采用率统计**：管理台 **Dashboard** 的 TOTP 卡片显示已启用人数、总用户数与采用率。
- **按用户查看或禁用 TOTP**：界面**没有**入口，需要超级管理员通过管理接口处理（例如用户丢失验证器与备份码）；接口说明见 [Admin API](../../../api/admin.mdx)。

用户自助的开启、关闭与备份码在个人设置里完成（见[登录与账户](./authentication.mdx)）。

<Callout type="warn">
  用户管理界面**没有**按用户开关 TOTP 的入口，也没有「强制某人启用 2FA」的开关；现有能力是采用率统计 + 管理员兜底禁用。强制全员 2FA 由站点设置里的全局开关控制。
</Callout>

## 批量操作

在用户列表勾选多人后弹出底部工具条：

| 操作 | 说明 |
| --- | --- |
| 发送通知 | 打开通知对话框，向勾选用户逐个发送站内通知 |
| 激活 | 逐个激活 |
| 禁用 | 逐个禁用 |
| 删除 | 逐个删除，确认后不可恢复 |
| 强制修改密码 | 批量置位并通知 |
| 授予 / 移除密码豁免 | 逐个设置 |

批量操作没有事务回滚：单条失败不会回滚其余条目，完成后的计数可能与实际成功数不一致，涉及权限/状态冲突的用户请核对后再重试。

> **未实现 / Roadmap**：没有批量加入/移出团队、批量导出、CSV 导入/导出，界面也没有批量发送邮件入口（该能力目前仅通过管理接口提供，见 [Users API](../../../api/users.mdx)）。

## 用户角色

全局角色（可多选）决定系统级与管理台能力，团队角色决定团队内级别。内置 5 个角色与权限集见[角色与权限](./roles-permissions.mdx)：

| 角色 | 大致能力 |
| --- | --- |
| **Super Admin** | 全部权限，绕过一切检查 |
| **Admin** | 管理台读写 + 全团队资源权限 |
| **Team Admin** | Member + 团队设置与成员管理 |
| **Member** | 团队内创建/编辑/运行资源 |
| **Viewer** | 只读 + 使用，默认角色 |

团队角色（Owner/Admin/Member/Viewer）在**团队**页面维护，不在用户编辑对话框里改。

## 最佳实践

**✅ 推荐：**

- 定期复核用户列表，及时禁用离职人员（禁用即可立即阻断登录与 API 密钥）
- 创建后立刻指派最小必要的全局角色
- 特权账户强制启用 2FA，并为其设置正常的密码轮换策略
- 关注 Dashboard 的密码安全卡片，提前处理即将过期账户，而不是等锁定后救火
- 禁用、删除、改角色等操作前后留痕（审计日志自带）

**❌ 避免：**

- 多人共用管理员账户（审计日志无法区分责任人）
- 直接删除团队 Owner 的账户（团队会变成无 Owner 状态）
- 一次性整体替换角色集却漏掉某个角色
- 依赖「前端隐藏按钮」做权限控制——后端是独立校验的

## 故障排除

### 无法添加用户

1. 检查用户名、邮箱是否已被占用。
2. 检查邮箱格式是否合法。
3. 检查你的角色是否具备用户创建权限。

### 用户无法登录

1. 确认账户处于**活跃**状态（已禁用或待审核都无法登录）。
2. 确认密码正确；必要时先**强制修改密码**或直接设置新密码。
3. 确认账户未被登录策略锁定（默认 5 次失败锁定 15 分钟）。
4. 确认 TOTP 状态；用户丢失验证器时由超级管理员通过管理接口禁用 TOTP。
5. 到 Audit Logs 按用户排查异常登录。

### 无法删除用户

- 目标是超级管理员 → 先摘掉超级管理员标记，或改用禁用。
- 目标是团队 Owner → 后端**不会**阻止删除，但团队会失去 Owner；先在团队里转让所有权再删除。
- 其他情况删除都会成功，务必确认上述级联清单（对话、API 密钥、成员关系会一并消失）。

### 改角色被拒绝

用户仍是某些团队的 Owner/Admin，而新角色集里没有团队管理权限。先到团队里降级他的成员角色，再改全局角色。
