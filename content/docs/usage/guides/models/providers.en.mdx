Clouisle connects multimodal models through a unified provider abstraction. **A provider is not an independently configurable entity**: there is no global provider registry with a default API key, timeout, or retry policy. Each model carries its own provider, request address, API key, and optional display name. So “configuring a provider” really means “registering a model with a provider selected”; see [Register models and authorize teams](./manage-models.mdx).

## Supported Providers

Choose a provider from the dropdown when registering a model. Without a custom request address, the platform uses the provider's official default.

| Provider | Notes |
| --- | --- |
| OpenAI | Official Chat Completions API |
| OpenAI Responses | OpenAI Responses API, mainly for image generation |
| Anthropic | Claude models |
| Google AI | Gemini models |
| Azure OpenAI | Requires an administrator to enter the Azure endpoint |
| DeepSeek | DeepSeek |
| Moonshot | Moonshot AI |
| Zhipu AI | Zhipu AI |
| Qwen | Alibaba Cloud Qwen |
| Baichuan | Baichuan AI |
| MiniMax | MiniMax |
| Volcengine | Volcengine Ark |
| SiliconFlow | SiliconFlow |
| xAI (Grok) | xAI |
| Ollama | A local or self-hosted Ollama service |
| Runway | Video generation |
| Pika | Video generation |
| Luma AI | Video generation |
| Kling | Kling video generation |
| Stability AI | Image generation |
| Midjourney | Requires a self-built proxy and has no default address |
| TypeSafe AI | Decision models |
| OpenAI Compatible | Any compatible API; the integrator supplies the address |

The request address resolves in this order: the model's own address → the model type's dedicated default → the provider default. Clearing the address therefore does not fail; it falls back to the default. This is also why a provider's speech models and chat models use different addresses.

<Callout type="info">
  Besides official defaults, three **model-type-specific** default addresses apply only when the model has no address of its own: Volcengine text-to-speech, Volcengine audio generation, and the TypeSafe decision model.
</Callout>

### OpenAI vs. OpenAI Responses

Both share a default address but use different protocols:

- **OpenAI** uses standard Chat Completions and is the usual choice for chat, embeddings, and speech.
- **OpenAI Responses** uses OpenAI's Responses API and is currently used for **image generation** (supporting size, quality, background, output format, and other specific parameters).

<Callout type="warn">
  OpenAI Responses behavior only applies to image generation. A chat model configured as OpenAI Responses still runs as standard compatible chat and does not gain Responses-specific semantics; if the upstream only needs standard chat completion, choose OpenAI. Model discovery uses the same path for both.
</Callout>

### How Providers Appear in the UI

Providers need no separate registration: model cards, the sidebar, and node dropdowns render the provider icon and name directly. Icons come from built-in provider artwork — OpenAI Responses uses the OpenAI icon and Azure OpenAI uses the Azure icon; OpenAI Compatible shows a gateway icon and guesses the model family from the model name prefix. Names are localized in the UI language (for example “DeepSeek”, “Moonshot”, “Zhipu AI”, “Qwen”, “Baichuan”, “Kling”, “Volcengine Ark”, “OpenAI Compatible”); a custom display name takes precedence, and unknown identifiers show the raw code.

## Model Types

There are nine model types, independent of providers:

| Model type | Description | Providers supported at runtime |
| --- | --- | --- |
| Chat | Chat and text completion (streaming, function calling) | OpenAI, Anthropic, Google AI, xAI, Azure OpenAI, DeepSeek, Moonshot, Zhipu AI, Qwen, Baichuan, MiniMax, Volcengine, SiliconFlow, Ollama, OpenAI Compatible (other identifiers run in compatible mode) |
| Embedding | Text vector embeddings (knowledge bases, memory retrieval) | 15: OpenAI, Google AI, DeepSeek, Moonshot, Zhipu AI, Qwen, Baichuan, MiniMax, Volcengine, SiliconFlow, xAI, Ollama, OpenAI Compatible, Azure OpenAI, OpenAI Responses |
| Rerank | Reordering retrieval results | Any; by default the chat model reranks, while SiliconFlow or native rerank mode calls a native rerank endpoint |
| TTS | Text to speech | OpenAI, Azure OpenAI, Volcengine, MiniMax |
| STT | Speech to text | OpenAI, Azure OpenAI |
| Audio generation | Generate audio from a prompt | Volcengine only |
| Text to image | Image generation | OpenAI, OpenAI Responses, Azure OpenAI, OpenAI Compatible, SiliconFlow, Google AI, Runway, Luma AI, Stability AI, Volcengine, MiniMax |
| Text to video | Video generation | Runway, Luma AI, Kling, Pika, SiliconFlow, Volcengine, MiniMax, Qwen |
| Decision | Typed decisions (choice/score/yes-no, non-generative) | TypeSafe AI **only** |

Only two combinations are validated on create/update: **Embedding** must use one of the providers listed above, and **Decision** must be TypeSafe AI. Other mismatches are **not** rejected at save time:

<Callout type="error">
  For example, Anthropic + Embedding or Stability AI + Text to video saves normally but fails with an “unsupported provider” error on the first real call. Knowledge bases and media nodes can therefore expose configuration errors only after saving — always verify with **Test connection** right after registering.
</Callout>

<Callout type="info">
  The decision model is a TypeSafe AI proprietary protocol: instead of chat completion it takes a state plus a typed question and returns answers with probability distributions, consumed by workflow **Decision** nodes.
</Callout>

## Remote Model Discovery

**Discover models** lists what a provider actually exposes before you save, avoiding hand-typed model names. Credentials are used only for that discovery request and are never stored.

Discovery supports **16 providers**: OpenAI, OpenAI Responses, Anthropic, Google AI, DeepSeek, Moonshot, Zhipu AI, Qwen, Baichuan, MiniMax, Volcengine, SiliconFlow, xAI, Ollama, TypeSafe AI, and OpenAI Compatible. Azure OpenAI, Runway, Pika, Luma AI, Kling, Stability AI, and Midjourney do **not** support discovery and report that the provider does not support it. Every provider except Ollama requires an API key.

### Discovery prerequisites

- **The request address must pass the site endpoint allowlist**, otherwise it is rejected before any request is made.
- The address must be `http(s)://host[:port]` with no query string, fragment, username/password, backslash, or path starting with `//`; a trailing `/` is stripped.
- Redirects are not followed, so credentials cannot be forwarded across origins.
- At most **200** models are returned; entries with overlong or duplicate names are skipped.
- Results include model name, context length, maximum output, and capabilities (vision, function calling, streaming, JSON mode), and can fill the create form directly.

### Discovering TypeSafe models behind a gateway

TypeSafe AI treats the configured request address as a gateway prefix and appends the model-list path, so both `https://gw.example.com/openai/v1` and `https://gw.example.com/api` work without hand-writing the discovery URL. The exact joining rules and examples are in the [model provider reference](../../../reference/model-providers.mdx).

## Endpoint Allowlist

The **model endpoint allowlist** in site settings is the master gate for model egress; discovery, connection tests, and runtime requests all obey it. Matching rules:

- Exact match on **scheme + host + port**, **ignoring the path**; `https://gateway.example.com/anything` and `https://gateway.example.com` are the same target.
- Non-default ports participate: `http://ollama.internal:11434` differs from `http://ollama.internal`.
- Twenty official addresses are preloaded; Midjourney has no default entry because it needs a self-built proxy.
- The allowlist holds at most 200 entries; **clearing the list blocks every model endpoint**.
- Removing an address immediately blocks later discovery, tests, and runtime requests — no restart needed.

Administrators can **turn off allowlist validation** under **Site settings > Security**. With it off, the allowlist is no longer compared, but address syntax is still validated and the saved list is preserved for re-enabling. Field details are in the [Site settings reference](/en/reference/site-settings).

<Callout type="warn">
  Turning off allowlist validation lets any resolvable host act as a model endpoint. Only do this when you trust every administrator who can create models and accept the data-egress risk. Prefer HTTPS for remote endpoints; plain HTTP is only for trusted private networks, otherwise API keys and model traffic travel in clear text.
</Callout>
