工具能让 Agent 真正做事：写文件、发消息、改工单、查生产库。能力越大，误操作的成本越高。**工具审批**给每个工具一个明确的执行边界：直接执行、始终拒绝，或者**停下来等调用者确认**。

审批只解决“这一次调用要不要人点头”，不替代连接身份、角色权限和网络白名单。

## 三种策略

| 策略 | 运行时行为 | 适合 |
| --- | --- | --- |
| **无需确认直接执行**（allow） | 调用立即执行 | 只读、无副作用、幂等的工具 |
| **始终拒绝**（deny） | 调用在产生副作用前失败 | 明确禁止 Agent 使用的高风险工具 |
| **需要调用者确认**（require_approval） | 暂停运行，等待发起人批准或拒绝 | 写操作、外部副作用、敏感读取 |

策略属于**工具本身**，不按团队、站点、入口或工作流再分层。团队页只是这些工具策略的集中编辑器；保存后修改的仍是该工具自己的策略。

## 在哪里配置

### 工具编辑器

创建或编辑工具时，找到**需要调用者确认**开关：

- 打开后，每次调用都会暂停等待确认。
- 关闭后按工具的默认决策执行；如果之前保存的是**始终拒绝**，关闭开关不会自动放行，仍需显式改成允许。

MCP 工具还可以按**操作名**添加覆盖规则。操作名必须与实际暴露的名称完全一致，例如 `tool:search`；没有匹配规则的操作继承默认决策。

### 团队 → 工具审批

1. 进入**当前团队**页面（`/app/team`）。
2. 切换到**工具审批**标签。
3. 列表显示团队可见的内置、自定义、MCP 与共享工具，以及每个工具的当前策略。
4. 点击**编辑策略**：
   - 选择默认决策：无需确认 / 始终拒绝 / 需要调用者确认。
   - MCP 工具可添加按操作名的覆盖。
5. 保存。变更会写入审计日志。

<Callout type="info">
  这个页面不会创建团队级、站点级或入口级审批层。它只修改单个工具自身的策略。私有工具只有创建者能改；共享工具由共享方团队管理，这里只读。
</Callout>

## 对话中的确认

当 Agent 调用一个需要确认的工具：

1. 运行进入**等待确认**，模型不会继续生成后续步骤。
2. 输入框上方出现确认卡，显示工具名称、说明和**查看操作详情**（敏感参数已脱敏）。
3. 选择**允许**或**拒绝**：
   - **允许**：从暂停点继续，执行这次调用。
   - **拒绝**：取消这次调用，运行继续或结束，工具不会执行。
4. 多个工具同时暂停时，每个调用单独确认，按原顺序恢复。

  <img src="/images/chat-tool-confirmation.png" alt="对话中的工具确认卡" />
  <figcaption>确认卡：工具名称、说明、脱敏后的操作详情，以及允许/拒绝</figcaption>

确认绑定到**发起这次调用的用户**：

- 团队成员、团队管理员和超级管理员都不能替别人确认。
- 刷新页面或切回会话会恢复待确认卡片；不要通过刷新来取消，应该明确拒绝或停止运行。
- 只有发起人能决定；决定后不能重复提交。
- 停止等待中的运行会取消待处理确认。

## API 与外部渠道

| 入口 | 行为 |
| --- | --- |
| **网页对话（JWT）** | 发起用户本人在确认卡上决定 |
| **Agent API（API 密钥）** | 只有**提交这次运行的同一把密钥**能决定；其他密钥、其他用户、已撤销密钥都拒绝 |
| **飞书 / 微信** | 机器人发送确认提示；发送 `/approve <execution UUID>` 批准，`/reject <execution UUID>` 拒绝 |
| **工作流** | 不创建审批关卡，包括 UI、工作流 API 密钥、嵌套/子工作流 |
| **嵌入、定时、后台入口** | 非交互，不弹确认；遇到必须确认的工具会直接失败（fail closed） |

API 密钥发起的运行在 `waiting` 事件处结束推流；重连时带 `after_sequence` 继续，或按执行 ID 读取并决定。完整请求体见 [Agents API](/api/agents)。

## 旧版审批配置

旧版本允许把审批人指定为某个用户或团队角色。这个方式已移除：

- 历史配置仍保留在数据库中，不会被静默转换。
- 运行时遇到这类策略会在工具执行前失败，并提示重新配置。
- 管理员需要在工具编辑器或团队工具审批页显式改成 allow、deny 或“需要调用者确认”并保存。
- 升级时，包含旧审批人的未开始执行会被取消，不会自动恢复。

## 审计

以下动作会写入审计日志：

- 批准或拒绝一次工具执行。
- 修改工具的审批策略。

记录包含操作者、认证方式（JWT / API 密钥）、团队与工具标识、执行与运行 ID、结果和错误码；**不记录**工具参数、凭证、密钥材料、审批理由。

## 常见问题

### 为什么确认卡没有出现？

检查工具当前策略是否为“需要调用者确认”。如果 Agent 在改策略前已经启动，重新发起一轮；旧运行不会因为策略变化而自动暂停。

### 能不能让团队管理员代确认？

不能。确认只属于发起调用的用户。这是为了避免跨用户授权和“替别人放行”的风险。

### 工作流为什么没有审批？

工作流是非交互执行，无法等待人工确认。需要保护的写操作应该放在 Agent 对话里，或改用不需要确认的只读工具。

### 升级后工具报“旧版审批人”

旧策略包含用户或团队角色审批人。在工具编辑器或团队工具审批页重新保存为支持的三种决策之一即可。
