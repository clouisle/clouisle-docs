Skills 是把提示词指令、运行脚本、依赖声明和执行约定封装在一起的可复用能力包。与单一 HTTP / 数据库工具不同，Skill 既可以只提供 Agent 需要遵循的详细规约（**指令型**），也可以在隔离沙箱里运行脚本并产出文件（**脚本型**）。

平台入口是**能力** > **Skills**（`/app/capabilities?tab=skills`）；平台管理员还可以在**管理后台** > **能力** > **Skills**（`/capabilities?tab=skills`）统一查看系统级与团队级 Skill，并从这里导入。

<Callout type="info">
查看 Skill 需要技能查看权限，导入与维护需要技能管理权限，沙箱测试需要沙箱执行权限。普通成员通常只有查看权限：可以在 Agent 编排里选用已安装的 Skill，但不能导入或修改。权限由平台管理员在角色中授予，见[角色与权限](/usage/guides/administration/roles-permissions)。
</Callout>

## Skill 包结构

每个 Skill 是包里的一个目录，目录根下必须有 `SKILL.md`（UTF-8 编码）：

```
my-skill/
├── SKILL.md              # 必须：元数据与提示词指令
├── scripts/
│   └── run.py            # 可选：脚本型 Skill 执行的脚本
└── assets/               # 可选：模板、规则或静态资源
```

`SKILL.md` 由 YAML 前置元数据与 Markdown 正文组成：

```markdown
---
name: text-summarizer
display_name: 文本摘要增强器
description: 提供长文本结构化摘要、要点提炼与多语言对照
version: 1.0.0
category: productivity
icon: FileText
x-clouisle:
  execution:
    mode: instructions
  input_schema:
    type: object
    properties:
      text:
        type: string
        description: 待摘要的原始文本
    required:
      - text
---

你是一个专业的长文本提炼专家。当用户提供长篇文档时，请按以下步骤处理：
1. 提取 3-5 条核心结论；
2. 输出要点表格；
3. 保留关键数据并给出事实溯源。
```

**必填**：`name`（小写字母、数字、下划线或中划线）与 `description`。**可选**：`display_name`（界面展示名，缺省用 `name`）、`version`、`category`、`icon`，以及 `x-clouisle` 下的执行模式与输入参数结构。正文就是 Agent 会读到的指令。

### 执行模式

| 模式 | 运行方式 | 适用场景 |
| --- | --- | --- |
| **指令型**（默认） | 不执行代码。`SKILL.md` 正文会作为规约注入 Agent 上下文，指导模型按固定流程工作。 | 写作规范、分析流程、代码审查准则、行业 SOP |
| **脚本型** | 在隔离沙箱里运行包内声明的脚本（Python / Node.js），返回标准输出、错误与生成的文件（产物）。 | 复杂计算、数据统计、图表绘制、批量文件转换 |

Skill 卡片与详情页会标明来源（**Zip**、**Git** 或**旧版**）；**旧版**表示由迁移前的沙箱 Skill 配置转为技能包。执行模式写在 `SKILL.md` 里，导入后不能在界面单独修改。

### 包限制与校验

- **ZIP 上传**：只接受 `.zip`，单文件上限 **50 MB**，解压后总大小上限 **50 MB**，最多 **500** 个文件，单个解压文件上限 **10 MB**。
- **禁止危险内容**：包内不能有符号链接、嵌套压缩包或 `../` 这类跨目录路径。
- **Git 仓库**：必须是公开的 HTTPS 仓库，可指定分支、标签或提交；拉取超时 **180 秒**。
- 缺少 `SKILL.md`、元数据格式错误或名称不合法的包会在预览里标为无效，不会安装。

## 导入 Skill 包

<Callout type="warn" title="Skill 只能通过导入创建">
平台**没有「新建 Skill」的手动入口**，创建 Skill 的唯一方式是导入 ZIP 或 Git 仓库。导入后只能调整**元数据**（显示名、描述、图标、分类、启用状态、默认配置）；要改 `SKILL.md` 正文或脚本内容，必须重新导入。
</Callout>

1. 前往**能力**页（`/app/capabilities`），切到 **Skills** 标签。
2. 点击右上角**导入 Skills**。
3. 选择来源：
   - **上传 Zip**：选择包含一个或多个 Skill 目录的 `.zip`。
   - **Git 仓库**：填写公开 HTTPS 仓库地址，可选填**分支、标签或提交**（如 `main`、`v1.0.0`）。
4. 点击**扫描预览**。预览表为每个 `SKILL.md` 目录列出一行：
   - **包路径**与 **Skill**（展示名 + 描述）。
   - **状态**：有效、冲突（团队里已有同名 Skill）、名称重复（同一来源里出现多次）。
   - **操作**：安装、更新、跳过。
5. 无冲突项默认勾选；冲突项默认不勾选，需要覆盖时手动勾选并选择**更新**（会用新包覆盖同名 Skill，名称与归属不变）。同一来源里重名的包默认只安装第一个。
6. 确认后点击**安装选中项**，列表随即出现新 Skill，状态为**已启用**。

## 查看 Skill 详情

点击列表中的 Skill 卡片（管理后台为名称）进入详情页，可看到：

- **状态**（已启用 / 已禁用）、**范围**（系统 / 团队）、分类、版本与来源。
- **包路径**、**参数**（`SKILL.md` 声明的输入参数名）与**更新时间**。
- **指令**正文，即 Agent 使用前会读到的完整规约。

详情页用来在上线前核对 Agent 将看到的说明与参数是否符合预期。

## 在 Agent 中绑定与调用

1. 打开目标 Agent 的编排页（`/app/apps/{agent_id}`）。
2. 在**工具**区域选择**添加工具/技能**，切到 **Skills** 分类。
3. 选择要启用的 Skill。选择器只列出**已启用**的 Skill。
4. 保存后，Agent 在对话与推理过程中会根据系统提示词和任务目标自主决定是否调用它。
5. 调试无误后**发布**。

## 启用状态

卡片与详情页都会显示**已启用** / **已禁用**：

- 禁用的 Skill 不会出现在 Agent 的工具选择器里；已绑定的 Skill 被禁用后，运行时也不会再调用它。
- 当前界面只展示状态，没有开关：需要停用或重新启用时，由平台管理员通过[技能 API](/api/skills) 调整。新导入的包默认启用。

## 运行测试

Skill 支持在隔离环境中先跑一次再上线，测试通过[技能 API](/api/skills) 的测试操作发起（界面暂未提供测试按钮）：

- **指令型**：直接返回 `SKILL.md` 的指令内容，用来预览 Agent 将读到的上下文，不执行任何代码。
- **脚本型**：在沙箱中执行脚本，返回运行成功或失败、耗时、标准输出、标准错误与产物文件列表，产物可下载。
- 输入参数需符合 `SKILL.md` 里声明的结构；参数缺失或类型不符会直接报校验错误。

脚本型 Skill 依赖平台已启用代码沙箱；沙箱不可用时测试与运行时调用都会失败，见[代码沙箱](/usage/concepts/sandbox)。

## 作用域与可见性

- **系统（System）**：不属于任何团队，全平台所有团队可用；只有平台管理员能导入、维护与删除。
- **团队（Team）**：只属于一个团队，仅该团队成员可见可用；团队管理员可管理。
- Skill **没有跨团队共享入口**：可见范围完全由系统级或团队级归属决定。需要跨团队复用，请让平台管理员导入为系统级 Skill。
- 已被 Agent 引用的 Skill **不能删除**，需先在对应 Agent 的编排中解除绑定；系统级 Skill 只有平台管理员能删除。

## 排查

### 导入失败

1. **文件过大**：确认 ZIP 未超过 `50MB`，解压后未超过 `50MB`。
2. **缺少 SKILL.md**：确认每个 Skill 目录根下存在大写的 `SKILL.md`，且为 UTF-8。
3. **元数据格式错误**：检查 YAML 缩进，确认 `name` 与 `description` 都已填写且名称只含小写字母、数字、下划线或中划线。
4. **Git 超时**：公开仓库拉取超过 `180` 秒会失败；确认仓库可公开访问、`ref` 存在。

### 执行报错

1. 查看测试返回的标准错误输出，定位脚本异常。
2. 脚本型 Skill 需确认声明的依赖能在沙箱环境中安装；平台沙箱需要管理员开启。
3. 核对输入参数是否符合 `SKILL.md` 中声明的类型与必填项。
