Clouisle 的持久化数据分布在 PostgreSQL、Qdrant、Redis 和上传存储。备份不能只保存数据库。

## 存储后端

站点设置（**站点设置** > **存储**）支持**本地文件系统**和**对象存储**两种上传后端，由 `upload_storage_backend` 切换（默认 `local`）。本地模式适合单 API 副本；API 扩展到多个副本时，需要 `ReadWriteMany` 共享卷。对象存储适合多副本和跨节点部署。

对象存储需要配置以下站点设置（均为数据库字段，不是环境变量）：`object_storage_endpoint`、`object_storage_bucket`、`object_storage_region`、`object_storage_access_key`、`object_storage_secret_key`；`object_storage_force_path_style` 默认 `true`（S3 兼容服务通常需要路径风格），`object_storage_secure` 默认 `true`（端点未写 scheme 时按 HTTPS 访问）。

同分类下还有两项容量相关设置：`kb_document_max_upload_size_mb`（知识库单文件上限，默认 `50`，范围 `1`–`1024`）与 `audit_log_retention_days`（审计日志保留天数，默认 `365`，范围 `30`–`3650`，归档目录 `audit_log_archive_path` 默认 `/var/log/clouisle/audit_archives`）。

## Compose 卷

| 卷 | 服务 | 内容 |
| --- | --- | --- |
| `postgres_data` | `db`（`/var/lib/postgresql/data`） | 业务、审计、配置和元数据 |
| `qdrant_data` | `qdrant`（`/qdrant/storage`） | 向量集合 |
| `redis_data` | `redis`（`/data`） | Redis 持久化数据和任务/会话状态 |
| `uploads_data` | `api`（`/app/uploads`） | 用户上传和沙箱产物 |

Kubernetes 对应三个 PVC：`postgres-data`（`10Gi`，`RWO`）、`qdrant-data`（`10Gi`，`RWO`）、`uploads-data`（`10Gi`，`RWX`，只被 `api` 挂载）。单文件 manifest 的 Redis 用 `emptyDir`，不持久化；Helm 默认给 Redis 一个 `5Gi` PVC。

## 扩展规则

Worker 和 Sandbox Worker 可独立扩展。`beat` 必须一个副本。API 多副本需要共享上传存储或对象存储；Qdrant 和 PostgreSQL 应按其自身高可用方案扩展。

Worker 默认消费 `default,agent,knowledge,workflow` 4 个队列。高负载下若某类任务积压，可启动专用 Worker 独立扩容（如单独消费 `-Q agent` 加速 AgentRun 执行，或 `-Q knowledge` 处理知识库）。

扩展前确认数据库连接池：PostgreSQL 默认 `max_connections` 为 100，每个应用进程拥有独立连接池。如遇到连接竞争，结合 `DB_AGGREGATE_CONCURRENCY` 控制聚合并发，避免盲目调大连接池，详见[数据库维护与索引调优](./database-maintenance.mdx)。此外需确认供应商限速和磁盘 I/O。

## 容量检查

监控 PostgreSQL 数据库、pg_search 索引、Qdrant 集合、Redis 内存和上传目录。文档数量增长会同时增加原始文件、分块、Token 统计、向量和全文索引容量。
